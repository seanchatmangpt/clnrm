### Issue #2: Fixed 500ms Flush Timeout (Inefficient)

**Problem:**
```rust
// ❌ OLD: Fixed timeout regardless of network conditions
std::thread::sleep(Duration::from_millis(500));
```

**Impact:**
- Too short for slow networks → data loss
- Too long for fast networks → unnecessary wait
- No adaptation to actual export performance

**Solution:**
Implemented `AdaptiveFlush` with statistics-based timeout calculation:

```rust
pub struct AdaptiveFlush {
    stats: ExportStatistics,
    base_timeout: Duration,  // 500ms minimum
    max_timeout: Duration,   // 10s maximum
}

impl AdaptiveFlush {
    pub fn calculate_timeout(&self) -> Duration {
        let success_rate = self.stats.success_rate();
        let p95 = self.stats.p95_latency();

        if success_rate >= 0.999 {
            p95 * 1.10  // >99.9% success: tight tolerance
        } else if success_rate >= 0.99 {
            p95 * 1.25  // >99% success: moderate tolerance
        } else if success_rate >= 0.95 {
            p95 * 1.50  // >95% success: loose tolerance
        } else {
            self.max_timeout  // <95% success: max timeout (network issues)
        }
    }
}
```

**Files Modified:**
- `crates/clnrm-core/src/telemetry.rs` - Updated `OtelGuard::Drop` to use adaptive timeouts

### 2. Adaptive Flush Module

**Location:** `crates/clnrm-core/src/telemetry/adaptive_flush.rs`
**Lines of Code:** 350
**Purpose:** Calculate optimal flush timeouts based on export statistics

**Key Components:**

```rust
pub struct ExportStatistics {
    attempts: Arc<Mutex<VecDeque<ExportAttempt>>>,  // Circular buffer
    max_attempts: usize,  // Default: 1000
}

impl ExportStatistics {
    pub fn success_rate(&self) -> f64;  // 0.0 to 1.0
    pub fn p95_latency(&self) -> Duration;  // 95th percentile
    pub fn failed_exports(&self) -> usize;
}

pub struct AdaptiveFlush {
    stats: ExportStatistics,
    base_timeout: Duration,  // Minimum: 500ms
    max_timeout: Duration,   // Maximum: 10s
}

impl AdaptiveFlush {
    pub fn calculate_timeout(&self) -> Duration;
    pub fn is_healthy(&self) -> bool;  // >99.9% success
}
```

**Algorithm:**

1. **Track all export attempts** (success/failure + duration)
2. **Calculate P95 latency** (95th percentile of export times)
3. **Adjust buffer based on success rate:**
   - >99.9% success → P95 + 10% (tight tolerance)
   - >99.0% success → P95 + 25% (moderate tolerance)
   - >95.0% success → P95 + 50% (loose tolerance)
   - <95.0% success → Max timeout (10s) - network issues
4. **Clamp result** between base_timeout (500ms) and max_timeout (10s)

**Target:** >99.9% export success rate (1 failure per 1000 exports allowed)

### 4. Integration with OtelGuard

**Location:** `crates/clnrm-core/src/telemetry.rs`
**Changes:**

```rust
pub struct OtelGuard {
    tracer_provider: SdkTracerProvider,
    meter_provider: Option<SdkMeterProvider>,
    logger_provider: Option<SdkLoggerProvider>,
    export_monitor: Option<ExportMonitor>,
    adaptive_flush: Option<AdaptiveFlush>,  // ✅ NEW (v1.3.0)
}

impl Drop for OtelGuard {
    fn drop(&mut self) {
        // ✅ NEW: Calculate adaptive flush timeout
        let flush_timeout = if let Some(ref adaptive) = self.adaptive_flush {
            let (timeout, diagnostics) = adaptive.calculate_timeout_with_diagnostics();
            tracing::info!("🔄 Using adaptive flush timeout: {}", diagnostics);
            timeout
        } else {
            Duration::from_millis(500)  // Fallback
        };

        // Flush with adaptive timeout
        self.tracer_provider.force_flush()?;
        std::thread::sleep(flush_timeout);  // ✅ Adaptive instead of fixed 500ms

        // ... rest of shutdown
    }
}
```
