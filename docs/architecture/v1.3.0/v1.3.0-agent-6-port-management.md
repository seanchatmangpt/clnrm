## Current State (v1.2.1)

### Existing Implementation

**WeaverController Port Discovery**:
```rust
fn find_available_port(start: u16, end: u16) -> Result<u16> {
    for port in start..=end {
        match TcpListener::bind(("127.0.0.1", port)) {
            Ok(_) => return Ok(port),
            Err(_) => continue,
        }
    }
    Err(CleanroomError::validation_error("No available ports in range"))
}

fn find_available_port_with_fallback() -> Result<u16> {
    // Try primary range (4317-4327)
    if let Ok(port) = Self::find_available_port(4317, 4327) {
        return Ok(port);
    }
    // Fallback to secondary range (5317-5327)
    warn!("Primary OTLP port range exhausted, trying fallback");
    Self::find_available_port(5317, 5327)
}
```

**Current Ranges**:
- **OTLP Primary**: 4317-4327 (11 ports)
- **OTLP Fallback**: 5317-5327 (11 ports)
- **Admin Primary**: 8080-8090 (11 ports)
- **Admin Fallback**: 9080-9090 (11 ports)

### Current Strengths

✅ **Automatic port discovery** with TcpListener validation
✅ **Fallback ranges** prevent exhaustion in congested environments
✅ **Process cleanup** (`cleanup_old_weaver_processes()`) prevents orphaned processes
✅ **Explicit telemetry flush** ensures complete data delivery
✅ **Cross-platform** (Unix/Windows process cleanup)

### Current Limitations

❌ **Race condition**: Port may be bound between discovery and Weaver startup
❌ **No atomicity**: Multiple processes can discover the same "available" port
❌ **Fixed ranges**: Hardcoded port ranges not configurable by users
❌ **Sequential discovery**: Always tries 4317, 4318, 4319... (predictable)
❌ **No health check**: Admin port not validated beyond process state
❌ **No port reservation**: Ports released immediately after discovery check

## Problem Statement

### The Race Condition Problem

```
Timeline of Port Conflict:

T0: Process A discovers port 4317 is available (TcpListener succeeds)
T1: Process A releases TcpListener (port becomes available again)
T2: Process B discovers port 4317 is available (TcpListener succeeds)
T3: Process A starts Weaver on port 4317 (succeeds)
T4: Process B starts Weaver on port 4317 (FAILS - address in use)
```

**Critical Issue**: The window between discovery (T0-T1) and binding (T3) is unprotected.

### Parallel CI/CD Challenges

**Scenario**: GitHub Actions running 10 parallel jobs on same runner:

```yaml
jobs:
  test:
    strategy:
      matrix:
        test_suite: [unit, integration, e2e, performance, security, ...]
    runs-on: ubuntu-latest
    steps:
      - run: clnrm run tests/ --validate
```

**Problem**: All 10 jobs discover port 4317 simultaneously, causing 9 failures.

### Configuration Inflexibility

**User Request**: "I want to use ports 6000-6010 for OTLP because my company reserves 4300-4400 range."

**Current Solution**: ❌ None - must modify source code

## Architecture Decision

### Decision 1: Atomic Port Locking with File-Based Locks

**Rationale**: Use filesystem locks (`flock` on Unix, `LockFileEx` on Windows) to atomically reserve ports across processes.

**Pattern**:
```
1. Discover port via TcpListener (validates port is bindable)
2. Immediately create lock file: /tmp/clnrm_port_{port}.lock
3. Acquire exclusive flock on lock file
4. Start Weaver (port guaranteed reserved)
5. Release lock on process exit (via Drop trait)
```

**Why filesystem locks?**:
- ✅ Cross-process coordination (works across unrelated processes)
- ✅ OS-enforced atomicity (no race conditions)
- ✅ Automatic cleanup on crash (OS releases locks when process exits)
- ✅ Standard approach (used by systemd, Docker, PostgreSQL)

### Decision 2: User-Configurable Port Ranges via TOML

**Rationale**: Enable deployment flexibility without code changes.

**Pattern**:
```toml
[test.live_check.ports]
otlp_grpc = 0              # 0 = auto-discover
admin = 0                  # 0 = auto-discover
primary_range = [4317, 4327]
fallback_range = [5317, 5327]
admin_primary = [4320, 4330]
admin_fallback = [5320, 5330]
```

**Why TOML configuration?**:
- ✅ User control without recompilation
- ✅ Per-test customization (different suites, different ports)
- ✅ Environment-specific ranges (dev vs CI vs prod)
- ✅ Schema validation via clnrm's existing config system

### Decision 3: Smart Discovery Strategies

**Rationale**: Reduce predictability and improve parallelism.

**Strategies**:

1. **Sequential (Default)**: Try 4317, 4318, 4319... (predictable, fast for single process)
2. **Random**: Shuffle range before iteration (reduces collisions in parallel scenarios)
3. **Hash-Based**: Derive starting port from PID/timestamp (deterministic but distributed)

**Configuration**:
```toml
[test.live_check.ports.advanced]
discovery_strategy = "random"  # "sequential" | "random" | "hash"
```

### Decision 4: Admin Port Health Validation

**Rationale**: Verify Weaver is actually ready, not just started.

**Pattern**:
```rust
fn wait_for_weaver_ready(&mut self) -> Result<()> {
    const MAX_TIMEOUT: Duration = Duration::from_secs(30);
    const INITIAL_DELAY: Duration = Duration::from_millis(100);

    let admin_port = self.config.admin_port;
    let health_url = format!("http://localhost:{}/health", admin_port);

    loop {
        match reqwest::blocking::get(&health_url) {
            Ok(response) if response.status().is_success() => return Ok(()),
            _ => thread::sleep(INITIAL_DELAY),
        }
    }
}
```

**Why HTTP health check?**:
- ✅ Verifies actual server readiness (not just process existence)
- ✅ Detects startup failures early
- ✅ Aligns with production readiness patterns

## Component Design

### Component 1: PortLock (Atomic Locking Primitive)

```rust
/// Atomic port lock using filesystem locks
///
/// Ensures exclusive access to a port across all processes.
/// Lock is automatically released on Drop (even on panic/crash).
pub struct PortLock {
    /// Port number being locked
    port: u16,
    /// Lock file path
    lock_path: PathBuf,
    /// Lock file handle (held until drop)
    lock_file: File,
}

impl PortLock {
    /// Attempt to acquire exclusive lock on port
    ///
    /// # Arguments
    /// * `port` - Port number to lock
    /// * `timeout` - Maximum time to wait for lock
    ///
    /// # Returns
    /// * `Ok(PortLock)` - Lock acquired successfully
    /// * `Err(Timeout)` - Another process holds the lock
    /// * `Err(IoError)` - Failed to create lock file
    pub fn try_lock(port: u16, timeout: Duration) -> Result<Self> {
        let lock_path = Self::lock_path(port);

        // Create lock file (or open existing)
        let lock_file = OpenOptions::new()
            .create(true)
            .write(true)
            .open(&lock_path)?;

        // Attempt to acquire exclusive lock with timeout
        #[cfg(unix)]
        {
            use nix::fcntl::{flock, FlockArg};
            let fd = lock_file.as_raw_fd();
            flock(fd, FlockArg::LockExclusiveNonblock)?;
        }

        #[cfg(windows)]
        {
            use windows::Win32::Storage::FileSystem::LockFileEx;
            // Windows implementation...
        }

        Ok(Self { port, lock_path, lock_file })
    }

    /// Get lock file path for port
    fn lock_path(port: u16) -> PathBuf {
        #[cfg(unix)]
        let base_dir = PathBuf::from("/tmp");

        #[cfg(windows)]
        let base_dir = std::env::temp_dir();

        base_dir.join(format!("clnrm_port_{}.lock", port))
    }
}

impl Drop for PortLock {
    fn drop(&mut self) {
        // Lock automatically released when file closed
        // Explicitly remove lock file for cleanup
        let _ = std::fs::remove_file(&self.lock_path);
    }
}
```

**Design Rationale**:
- Uses `Drop` trait for automatic lock release (RAII pattern)
- Supports timeout to prevent indefinite blocking
- Cross-platform (Unix flock, Windows LockFileEx)
- Lock file in /tmp for automatic cleanup on reboot

    Sequential,
    /// Random shuffle (better for parallel CI)
    Random,
    /// Hash-based starting point (PID-based)
    Hash,
}

    fn default() -> Self {
        Self::Sequential
    }

- Serde defaults ensure backward compatibility
- Tuple ranges `(start, end)` for clean TOML syntax
- Advanced section separates power-user features
- Validation in separate impl (validate ranges, timeouts)

### Component 3: Enhanced WeaverController

```rust
impl WeaverController {
    /// Find available port with atomic locking
    ///
    /// # Arguments
    /// * `config` - Port discovery configuration
    /// * `range` - (start, end) port range to search
    ///
    /// # Returns
    /// * `Ok((port, lock))` - Available port and its lock
    /// * `Err(NoPortsAvailable)` - All ports in range are locked/used
    fn find_available_port_atomic(
        config: &PortDiscoveryConfig,
        range: (u16, u16),
    ) -> Result<(u16, Option<PortLock>)> {
        let (start, end) = range;

        // Generate port sequence based on strategy
        let ports = match config.advanced.discovery_strategy {
            DiscoveryStrategy::Sequential => {
                (start..=end).collect::<Vec<_>>()
            }
            DiscoveryStrategy::Random => {
                let mut ports = (start..=end).collect::<Vec<_>>();
                use rand::seq::SliceRandom;
                ports.shuffle(&mut rand::thread_rng());
                ports
            }
            DiscoveryStrategy::Hash => {
                // Hash PID to determine starting offset
                use std::collections::hash_map::DefaultHasher;
                use std::hash::{Hash, Hasher};
                let mut hasher = DefaultHasher::new();
                std::process::id().hash(&mut hasher);
                let offset = (hasher.finish() as u16) % (end - start + 1);

                // Rotate range to start at offset
                let mut ports = Vec::new();
                for i in 0..=(end - start) {
                    ports.push(start + ((offset + i) % (end - start + 1)));
                }
                ports
            }
        };

        // Try each port
        for port in ports {
            // Step 1: Check if port is bindable
            if TcpListener::bind(("127.0.0.1", port)).is_err() {
                debug!("Port {} not bindable, skipping", port);
                continue;
            }

            // Step 2: Attempt atomic lock
            if config.advanced.enable_atomic_locking {
                let timeout = Duration::from_millis(config.advanced.bind_timeout_ms);
                match PortLock::try_lock(port, timeout) {
                    Ok(lock) => {
                        info!("✅ Port {} locked atomically", port);
                        return Ok((port, Some(lock)));
                    }
                    Err(_) => {
                        debug!("Port {} locked by another process", port);
                        continue;
                    }
                }
            } else {
                // No atomic locking (legacy behavior)
                return Ok((port, None));
            }
        }

        Err(CleanroomError::validation_error(format!(
            "No available ports in range {}-{}. All ports locked or in use.",
            start, end
        )))
    }

    /// Wait for Weaver to become ready via HTTP health check
    fn wait_for_weaver_ready(&mut self, config: &PortDiscoveryConfig) -> Result<()> {
        let timeout = Duration::from_millis(config.advanced.health_check_timeout_ms);
        let start = Instant::now();
        let admin_port = self.config.admin_port;
        let health_url = format!("http://localhost:{}/health", admin_port);

        debug!("Health check URL: {}", health_url);

        // Exponential backoff
        let mut delay = Duration::from_millis(100);
        const MAX_DELAY: Duration = Duration::from_millis(1000);

        loop {
            // Check timeout
            if start.elapsed() > timeout {
                return Err(CleanroomError::timeout_error(format!(
                    "Weaver health check timed out after {}ms. URL: {}",
                    timeout.as_millis(),
                    health_url
                )));
            }

            // Check process state
            if let Some(ref mut process) = self.live_check_process {
                if let Ok(Some(status)) = process.try_wait() {
                    return Err(CleanroomError::internal_error(format!(
                        "Weaver exited during health check: {}",
                        status
                    )));
                }
            }

            // Attempt HTTP health check
            match reqwest::blocking::Client::builder()
                .timeout(Duration::from_secs(2))
                .build()
            {
                Ok(client) => match client.get(&health_url).send() {
                    Ok(response) if response.status().is_success() => {
                        info!("✅ Weaver health check passed ({}ms)", start.elapsed().as_millis());
                        return Ok(());
                    }
                    Ok(response) => {
                        debug!("Health check returned {}, retrying...", response.status());
                    }
                    Err(e) => {
                        debug!("Health check failed: {}, retrying...", e);
                    }
                },
                Err(e) => {
                    debug!("Failed to create HTTP client: {}", e);
                }
            }

            // Wait before retry (exponential backoff)
            thread::sleep(delay);
            delay = std::cmp::min(delay * 2, MAX_DELAY);
        }
    }
}
```

**Design Rationale**:
- Returns `(port, lock)` tuple to transfer ownership of lock
- Lock stored in WeaverController (via `Option<PortLock>`)
- Lock automatically released when controller dropped
- Three discovery strategies balance predictability vs parallelism
- Exponential backoff prevents health check spam

### Lock Lifecycle

```rust
// Example lifecycle in WeaverController
struct WeaverController {
    otlp_lock: Option<PortLock>,
    admin_lock: Option<PortLock>,
    // ... other fields
}

impl WeaverController {
    fn start_and_coordinate(&mut self) -> Result<WeaverCoordination> {
        // Acquire locks
        let (otlp_port, otlp_lock) = Self::find_available_port_atomic(
            &self.config.port_config,
            self.config.port_config.primary_range,
        )?;

        let (admin_port, admin_lock) = Self::find_available_port_atomic(
            &self.config.port_config,
            self.config.port_config.admin_primary,
        )?;

        // Store locks (ownership transferred)
        self.otlp_lock = otlp_lock;
        self.admin_lock = admin_lock;

        // Start Weaver with locked ports
        self.start_weaver(otlp_port, admin_port)?;

        // Health check
        self.wait_for_weaver_ready(&self.config.port_config)?;

        Ok(WeaverCoordination {
            weaver_pid: self.process_id(),
            otlp_grpc_port: otlp_port,
            admin_port,
            ready_at: Instant::now(),
        })
    }
}

impl Drop for WeaverController {
    fn drop(&mut self) {
        // Locks automatically released when otlp_lock/admin_lock dropped
        // This happens even on panic or ctrl-c
    }
}
```

### Validation Rules

```rust
impl PortDiscoveryConfig {
    /// Validate port configuration
    pub fn validate(&self) -> Result<()> {
        // Check ranges are valid
        if self.primary_range.0 >= self.primary_range.1 {
            return Err(CleanroomError::config_error(
                "primary_range start must be less than end"
            ));
        }

        // Check ports are in valid range (1024-65535)
        if self.primary_range.0 < 1024 {
            return Err(CleanroomError::config_error(
                "Ports below 1024 require root privileges"
            ));
        }

        // Check ranges don't overlap
        if self.ranges_overlap(self.primary_range, self.admin_primary) {
            return Err(CleanroomError::config_error(
                "OTLP and admin port ranges must not overlap"
            ));
        }

        // Check timeouts are reasonable
        if self.advanced.bind_timeout_ms < 100 {
            return Err(CleanroomError::config_error(
                "bind_timeout_ms must be at least 100ms"
            ));
        }

        Ok(())
    }

    fn ranges_overlap(&self, r1: (u16, u16), r2: (u16, u16)) -> bool {
        !(r1.1 < r2.0 || r2.1 < r1.0)
    }
}
```

**v1.3.0 (Proposed)**:
```
Port Discovery:     15-60ms   (TcpListener + flock)

Weaver Startup:     1000ms    (process spawn)
Health Check:       100-2000ms (HTTP polling with exponential backoff)
─────────────────────────────
Total Startup:      1.6-3.6s  (median: ~2s)
```

**Overhead Delta**: +5-15ms for atomic locking, -900ms for faster health check (on average)

**Parallel CI Jobs** (10 jobs on same runner):

v1.2.1:
- Job 1: 2.5s (gets 4317)
- Job 2: 2.5s (gets 4318)
- Jobs 3-10: **FAIL** (race condition, retry 3x)

v1.3.0:
- All jobs: 2s startup (atomic locks prevent conflicts)
- Success rate: 100%
- Total time: ~2s (all jobs succeed immediately)

**Improvement**: 15-30x faster in parallel scenarios due to zero retries

### Resource Usage

**File Descriptors**:
- v1.2.1: 2 FDs (Weaver OTLP + admin sockets)
- v1.3.0: 4 FDs (Weaver sockets + 2 lock files)
- Delta: +2 FDs (negligible on modern systems)

**Disk I/O**:
- Lock file creation: ~1KB per lock
- Lock file cleanup: 1 unlink syscall
- Total: Minimal impact

**CPU**:
- Atomic locking: <1ms CPU time (flock syscall)
- Random shuffle: ~0.1ms for 11-port range
- Total: Negligible CPU overhead

## Alternatives Considered

### Alternative 1: Database-Based Coordination

**Approach**: Use SQLite/Redis for port allocation tracking

**Pros**:
- Centralized state
- Query capabilities
- Built-in transactions

**Cons**:
- ❌ External dependency (SQLite/Redis must be installed)
- ❌ Network latency (for Redis)
- ❌ Complex failure modes (what if DB is down?)
- ❌ Overkill for simple port allocation

**Decision**: ❌ Rejected - Filesystem locks are simpler and more reliable

### Alternative 2: Port Reservation Service

**Approach**: Standalone daemon managing port pool

**Pros**:
- Centralized coordination
- Advanced features (priorities, reservations)

**Cons**:
- ❌ Complex deployment (daemon must be running)
- ❌ Single point of failure
- ❌ Bootstrapping problem (what port does daemon use?)
- ❌ Overkill for clnrm's use case

**Decision**: ❌ Rejected - Too complex for incremental benefit

### Alternative 3: Fixed Port Allocation Table

**Approach**: Assign each test suite a fixed port range

**Pros**:
- Simple and predictable
- No discovery overhead

**Cons**:
- ❌ Inflexible (what if you need 11th test suite?)
- ❌ Wasted ports (many ranges idle)
- ❌ Manual coordination required

**Decision**: ❌ Rejected - Doesn't scale dynamically

### Alternative 4: Kernel-Based Ephemeral Ports

**Approach**: Let kernel assign ports via `bind(0)`

**Pros**:
- Guaranteed available
- Zero configuration

**Cons**:
- ❌ Unpredictable ports (hard to debug)
- ❌ Firewall rules difficult
- ❌ Monitoring/observability challenges
- ❌ Weaver must support port injection (doesn't currently)

**Decision**: ❌ Rejected - Loses control and observability

## Appendix A: Lock File Format

### Lock File Structure

**Path**: `/tmp/clnrm_port_{port}.lock`

**Content** (optional metadata):
```json
{
  "port": 4317,
  "pid": 12345,
  "process_name": "clnrm",
  "locked_at": "2025-10-31T12:34:56Z",
  "purpose": "weaver_otlp"
}
```

**Notes**:
- Metadata is optional (flock works with empty files)
- Useful for debugging (see which process holds lock)
- Written atomically before flock acquisition

### Lock Cleanup Strategy

**Automatic Cleanup**:
- Process exit (normal) → Drop trait releases lock
- Process crash/panic → OS releases flock automatically
- System reboot → /tmp cleared on most systems

**Manual Cleanup** (if needed):
```bash
# Find stale locks
find /tmp -name "clnrm_port_*.lock" -mtime +1 -ls

# Remove stale locks
find /tmp -name "clnrm_port_*.lock" -mtime +1 -delete
```

**Systemd Timer** (optional):
```systemd
# /etc/systemd/system/clnrm-cleanup.timer
[Unit]
Description=Clean up stale clnrm port locks

[Timer]
OnBootSec=5min
OnUnitActiveSec=1h

[Install]
WantedBy=timers.target
```

## Appendix B: Error Codes

### Port Management Error Codes

| Code | Name | Description | User Action |
|------|------|-------------|-------------|
| **PM001** | NoPortsAvailable | All ports in range are in use | Increase port range or stop services |
| **PM002** | LockTimeout | Failed to acquire lock within timeout | Wait for other process to finish |
| **PM003** | InvalidRange | Port range configuration is invalid | Fix TOML configuration |
| **PM004** | PrivilegedPort | Attempted to use port <1024 | Use ports ≥1024 or run as root |

| **PM006** | LockFileIOError | Failed to create lock file | Check /tmp permissions |
