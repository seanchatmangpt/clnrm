# clnrm v1.3.0 Configuration Architecture Assessment

**Evaluator**: Architecture Evaluator #1
**Date**: 2025-10-31
**Scope**: TOML Configuration Layer (Phase 1 Implementation)
**Status**: Comprehensive Analysis Complete

---

## Executive Summary

The current configuration implementation (v1.3.0 Phase 1) is **solid and production-ready** with excellent separation of concerns, comprehensive validation, and proper backward compatibility. However, there are **significant opportunities** to modernize using the Rust ecosystem's best-in-class configuration crates.

**Key Findings**:
- ✅ **Strengths**: Clean structure, comprehensive validation, zero breaking changes
- ⚠️ **Opportunities**: Multi-source config, declarative validation, hot-reload capability
- 🎯 **Recommendation**: Selective modernization using `figment` + `validator` + `serde_with`

**Risk Level**: LOW (all proposed changes are non-breaking enhancements)

### 1.3 Weaknesses and Technical Debt

#### ⚠️ 1. Single-Source Configuration (No Layering)
**Current**:
```rust

```

**Problem**:
- Cannot override TOML values with environment variables
- Cannot merge global config (`~/.clnrm/config.toml`) with test-specific config
- CLI flags must be handled separately in command layer

**Impact**: Medium - Users have to manually edit TOML for every environment

#### ⚠️ 2. Manual Validation (Code Duplication)
**Current**:
```rust

    return Err(CleanroomError::validation_error(format!(
        "Coverage threshold must be between 0.0 and 100.0, got {}",
        self.coverage_threshold
    )));

```

**Problem**:
- 20 default functions (boilerplate)
- 4 validation methods with similar patterns
- Error messages manually constructed
- Cannot generate documentation from validation rules

**Impact**: Medium - Maintenance burden, potential for inconsistent error messages

#### ⚠️ 3. No Hot Reload Support
**Current**:
```rust
pub fn load_config_from_file(path: &Path) -> Result<TestConfig> {
    let content = std::fs::read_to_string(path)?;
    // ... parse once, never watch for changes
}
```

**Problem**:
- Config changes require process restart
- No file watching capability
- Development iteration slower

**Impact**: Low - Nice-to-have for dev workflow, not critical

#### ⚠️ 4. Limited Type Transformations
**Current**:
```rust

```

**Problem**:
- Cannot parse human-friendly durations: `"5s"`, `"100ms"`
- Cannot parse percentages: `"80%"` → `0.8`
- Limited type coercion

**Impact**: Low - Current design is explicit and safe, just less ergonomic

#### ⚠️ 5. No Schema Generation for Documentation
**Current**:
- Documentation is manually written in markdown
- TOML examples maintained separately
- No single source of truth for schema

**Problem**:
- TOML schema and docs can drift
- Cannot auto-generate JSON Schema for tooling
- No IDE autocomplete support

**Impact**: Low - Docs are excellent, but automation would reduce maintenance

## Section 2: Crate Recommendations

### 2.1 Configuration Loading: `figment`

**Recommendation**: ✅ **USE**

**Rationale**:
```rust
// Current: Single-source only
let config = parse_toml_config(&content)?;

// With figment: Multi-source with precedence
let config: WeaverConfig = Figment::new()
    .merge(Toml::file("~/.clnrm/config.toml"))  // Global defaults
    .merge(Toml::file("tests/my_test.toml"))    // Test-specific
    .merge(Env::prefixed("CLNRM_WEAVER_"))      // Environment overrides
    .merge(Serialized::defaults(cli_flags))     // CLI highest precedence
    .extract()?;
```

**Benefits**:
1. **Multi-source merging**: TOML → Env → CLI (proper precedence)
2. **Zero breaking changes**: Existing TOML files work unchanged
3. **Solves real user pain**: No more editing TOML for different environments
4. **Industry standard**: Used by Rocket, Shuttle, many production systems

**Integration Cost**: **LOW**
- Add `figment = { version = "0.10", features = ["toml", "env"] }` to Cargo.toml
- Update `load_config_from_file()` to use Figment instead of raw `toml::from_str()`
- Existing validation logic unchanged

**Risk**: **VERY LOW**
- Figment is stable (v0.10), well-maintained
- Non-breaking: just wraps existing serde deserialization
- Fallback: can still use `toml::from_str()` if needed

**Implementation Example**:
```rust
use figment::{Figment, providers::{Toml, Env, Format, Serialized}};
use serde::Deserialize;

impl WeaverConfig {
    /// Load configuration with layered sources (v1.3.0+)
    pub fn load() -> Result<Self> {
        Figment::new()
            // 1. Built-in defaults (lowest precedence)
            .merge(Serialized::defaults(WeaverConfig::default()))
            // 2. Global config file
            .merge(Toml::file(Path::new("~/.clnrm/config.toml")).nested())
            // 3. Test-specific TOML (from current load path)
            .merge(Toml::file(Path::new("weaver.toml")).nested())
            // 4. Environment variables (CLNRM_WEAVER_REGISTRY_PATH, etc.)
            .merge(Env::prefixed("CLNRM_WEAVER_").split("_"))
            // 5. CLI flags (handled by command layer, merged last)
            .extract()
            .map_err(|e| CleanroomError::config_error(format!("Config load failed: {}", e)))
    }
}
```

**Verdict**: **HIGHLY RECOMMENDED** - Solves real problems, low risk, production-proven.

### 2.2 Validation: `validator` vs `garde`

**Recommendation**: ✅ **USE `validator`** (with caveats)

**Option A: `validator` (Mature, Widely Adopted)**
```rust
use validator::Validate;

#[derive(Debug, Deserialize, Validate)]
pub struct ValidationConfig {
    #[validate(range(min = 0.0, max = 100.0))]
    pub coverage_threshold: f64,

    #[validate(range(min = 1))]
    pub inactivity_timeout: u64,

    #[serde(default)]
    #[validate]  // Nested validation
    pub mode: ValidationMode,
}

impl WeaverConfig {
    pub fn validate(&self) -> Result<()> {
        self.validate()  // One line!
            .map_err(|e| CleanroomError::validation_error(e.to_string()))
    }
}
```

**Benefits**:
- Declarative: `#[validate(range(...))]` vs 5 lines of manual code
- Better error messages: `validator` generates consistent errors
- Less boilerplate: Eliminates 20+ default functions
- Self-documenting: Validation rules visible in struct definition

**Drawbacks**:
- Less control over error message formatting
- Some edge cases require custom validators
- Slightly more compile-time overhead

**Option B: `garde` (Modern, Type-Safe)**
```rust
use garde::Validate;

#[derive(Debug, Deserialize, Validate)]
pub struct ValidationConfig {
    #[garde(range(min = 0.0, max = 100.0))]
    pub coverage_threshold: f64,
}
```

**Benefits over `validator`**:
- Better type safety (uses const generics)
- More ergonomic API
- Better error handling

**Drawbacks**:
- Newer (less battle-tested than `validator`)
- Smaller ecosystem

**Recommendation**: **Use `validator` for v1.3.0**, consider `garde` for v2.0.0
- `validator` is stable, widely used, proven in production
- `garde` is promising but needs more time to mature

**Integration Cost**: **MEDIUM**
- Add `validator = { version = "0.18", features = ["derive"] }` to Cargo.toml
- Replace manual validation with `#[validate(...)]` attributes
- Update error handling to convert validator errors to CleanroomError
- Estimated effort: 2-4 hours

**Risk**: **LOW**
- `validator` is stable (v0.18), used by major projects (Actix, Rocket)
- Can coexist with manual validation (gradual migration)
- Fallback: keep manual validation if issues arise

**Verdict**: **RECOMMENDED** - Reduces boilerplate significantly, improves consistency.

## Section 3: Architecture Improvements

### 3.1 Configuration Sources: Multi-Source with Figment

**Current Architecture** (Single Source):
```
TOML File → parse_toml_config() → TestConfig → validate() → Runtime
```

**Proposed Architecture** (Multi-Source):
```
┌─────────────────────────────────────────────────────────────┐
│                     Configuration Sources                    │
│  (Merged in order, later sources override earlier ones)      │
└─────────────────────────────────────────────────────────────┘
    │
    ├─ 1. Built-in Defaults (WeaverConfig::default())
    │      Priority: LOWEST
    │
    ├─ 2. Global Config (~/.clnrm/config.toml)
    │      Priority: LOW
    │      Use Case: User's default preferences
    │
    ├─ 3. Test-Specific TOML (tests/my_test.toml)
    │      Priority: MEDIUM
    │      Use Case: Per-test configuration
    │
    ├─ 4. Environment Variables (CLNRM_WEAVER_*)
    │      Priority: HIGH
    │      Use Case: CI/CD overrides, dev environments
    │      Example: CLNRM_WEAVER_REGISTRY_PATH=/custom/registry
    │
    └─ 5. CLI Flags (--weaver-registry, --weaver-mode)
           Priority: HIGHEST
           Use Case: One-off overrides
           Example: clnrm run --weaver-mode=lenient
    │
    ↓
┌─────────────────────────────────────────────────────────────┐
│                    Figment::extract()                        │
│         Merges all sources, applies precedence rules         │
└─────────────────────────────────────────────────────────────┘
    │
    ↓
┌─────────────────────────────────────────────────────────────┐
│                  WeaverConfig (Validated)                    │
│                  config.validate()?                          │
└─────────────────────────────────────────────────────────────┘
    │
    ↓
┌─────────────────────────────────────────────────────────────┐
│              Runtime Config (Resolved Paths)                 │
│          config.to_runtime() → WeaverRuntimeConfig          │
└─────────────────────────────────────────────────────────────┘
```

**Implementation**:
```rust
use figment::{Figment, providers::{Toml, Env, Format, Serialized}};

impl WeaverConfig {
    /// Load configuration from multiple sources (v1.3.0+)
    pub fn load_multi_source(
        test_config_path: Option<&Path>,
        cli_overrides: Option<WeaverCliArgs>,
    ) -> Result<Self> {
        let mut figment = Figment::new()
            // 1. Built-in defaults
            .merge(Serialized::defaults(WeaverConfig::default()));

        // 2. Global config (optional)
        let global_config = dirs::home_dir()
            .map(|h| h.join(".clnrm/config.toml"));
        if let Some(path) = global_config {
            if path.exists() {
                figment = figment.merge(Toml::file(path));
            }
        }

        // 3. Test-specific TOML (if provided)
        if let Some(path) = test_config_path {
            figment = figment.merge(Toml::file(path));
        }

        // 4. Environment variables (CLNRM_WEAVER_*)
        figment = figment.merge(
            Env::prefixed("CLNRM_WEAVER_")
                .split("_")  // CLNRM_WEAVER_REGISTRY_PATH → registry_path
                .map(|key| key.as_str().to_lowercase().into())
        );

        // 5. CLI overrides (highest precedence)
        if let Some(cli) = cli_overrides {
            figment = figment.merge(Serialized::defaults(cli));
        }

        // Extract and validate
        let config: WeaverConfig = figment.extract()
            .map_err(|e| CleanroomError::config_error(format!("Config extraction failed: {}", e)))?;

        config.validate()?;
        Ok(config)
    }
}
```

**Benefits**:
- **Development**: Override registry path with `CLNRM_WEAVER_REGISTRY_PATH=/tmp/registry`
- **CI/CD**: Set strict mode with `CLNRM_WEAVER_VALIDATION_MODE=strict`
- **One-off testing**: `clnrm run --weaver-mode=lenient tests/`
- **Global defaults**: User sets preferred settings in `~/.clnrm/config.toml`

**Migration Path**: Non-breaking! Existing single-TOML workflow still works.

### 3.2 Validation Strategy: Hybrid Manual + Declarative

**Proposed Approach**: Use `validator` for simple cases, keep manual for complex logic

**Simple Cases** (80% of validation):
```rust
use validator::Validate;

#[derive(Debug, Deserialize, Validate)]
pub struct ValidationConfig {
    #[validate(range(min = 0.0, max = 100.0))]
    pub coverage_threshold: f64,

    #[validate(range(min = 1))]
    pub inactivity_timeout: u64,
}
```

**Complex Cases** (20% of validation):
```rust
impl WeaverConfig {
    pub fn validate(&self) -> Result<()> {
        // Use validator for simple field validation
        self.validate()
            .map_err(|e| CleanroomError::validation_error(e.to_string()))?;

        // Manual validation for complex logic
        if self.otlp_port == self.admin_port && self.otlp_port > 0 {
            return Err(CleanroomError::validation_error(
                "OTLP port and admin port must be different"
            ));
        }

        // Cross-field validation
        if let Some(ref validation) = self.validation {
            if validation.mode == ValidationMode::EightyTwenty
               && self.eighty_twenty.is_none() {
                return Err(CleanroomError::validation_error(
                    "80/20 mode requires [weaver.80_20] section"
                ));
            }
        }

        Ok(())
    }
}
```

**Benefits**:
- Eliminate ~150 lines of boilerplate range checking
- Consistent error messages for common validations
- Keep flexibility for complex cross-field validation

### 3.4 Hot Reload: File Watching with `notify`

**Use Case**: Development workflow
```rust
use notify::{Watcher, RecursiveMode, Event};

pub struct WeaverConfigWatcher {
    config: Arc<RwLock<WeaverConfig>>,
    watcher: RecommendedWatcher,
}

impl WeaverConfigWatcher {
    pub fn watch(path: &Path) -> Result<Self> {
        let config = Arc::new(RwLock::new(WeaverConfig::load_from_file(path)?));

        let config_clone = config.clone();
        let watcher = notify::recommended_watcher(move |res: Result<Event, _>| {
            if let Ok(event) = res {
                if event.kind.is_modify() {
                    // Reload config on file modification
                    if let Ok(new_config) = WeaverConfig::load_from_file(path) {
                        *config_clone.write().unwrap() = new_config;
                        tracing::info!("Config reloaded from {:?}", path);
                    }
                }
            }
        })?;

        watcher.watch(path, RecursiveMode::NonRecursive)?;

        Ok(Self { config, watcher })
    }

    pub fn get_config(&self) -> WeaverConfig {
        self.config.read().unwrap().clone()
    }
}
```

**Benefits**:
- Edit TOML during development, changes apply immediately
- No process restart needed
- Faster iteration

**Drawbacks**:
- Adds complexity
- File watching can be unreliable (platform-dependent)
- Not needed for production (config is immutable)

**Verdict**: **DEFER to v1.4.0+** - Nice dev experience, but not critical for v1.3.0.

## Section 4: Proposed Architecture

### 4.1 Recommended Architecture (v1.3.1)

**Goal**: Add multi-source configuration without breaking changes

```rust
//! Configuration loading with multi-source support (v1.3.1)

use figment::{Figment, providers::{Toml, Env, Format, Serialized}};
use serde::{Deserialize, Serialize};
use std::path::{Path, PathBuf};
use crate::error::{CleanroomError, Result};

/// Weaver live-check configuration (v1.3.1)
///
/// Supports loading from multiple sources with precedence:
/// 1. Built-in defaults (lowest)
/// 2. Global config (~/.clnrm/config.toml)
/// 3. Test-specific TOML
/// 4. Environment variables (CLNRM_WEAVER_*)
/// 5. CLI flags (highest)
#[derive(Debug, Deserialize, Serialize, Clone)]
pub struct WeaverConfig {
    #[serde(default = "default_true")]
    pub enabled: bool,

    #[serde(default = "default_registry_path")]
    pub registry_path: String,

    #[serde(default)]
    pub otlp_port: u16,

    #[serde(default)]
    pub admin_port: u16,

    #[serde(default = "default_output_dir")]
    pub output_dir: String,

    #[serde(default)]
    pub stream: bool,

    #[serde(default)]
    pub fail_fast: bool,

    #[serde(default)]
    pub validation: Option<ValidationConfig>,

    #[serde(default, rename = "80_20")]
    pub eighty_twenty: Option<EightyTwentyConfig>,

    #[serde(default)]

impl WeaverConfig {
    /// Load configuration from file (v1.3.0 compatible)
    pub fn load_from_file(path: &Path) -> Result<Self> {
        let content = std::fs::read_to_string(path)
            .map_err(|e| CleanroomError::config_error(format!("Failed to read config: {}", e)))?;

        let config: WeaverConfig = toml::from_str(&content)
            .map_err(|e| CleanroomError::config_error(format!("TOML parse error: {}", e)))?;

        config.validate()?;
        Ok(config)
    }

    /// Load configuration from multiple sources (v1.3.1+)
    ///
    /// Precedence (highest to lowest):
    /// 1. CLI flags (if provided)
    /// 2. Environment variables (CLNRM_WEAVER_*)
    /// 3. Test-specific TOML file (if provided)
    /// 4. Global config file (~/.clnrm/config.toml)
    /// 5. Built-in defaults
    pub fn load_multi_source(
        test_config_path: Option<&Path>,
        cli_overrides: Option<WeaverCliOverrides>,
    ) -> Result<Self> {
        let mut figment = Figment::new()
            .merge(Serialized::defaults(WeaverConfig::default()));

        // Global config (if exists)
        if let Some(home) = dirs::home_dir() {
            let global_path = home.join(".clnrm/config.toml");
            if global_path.exists() {
                figment = figment.merge(Toml::file(global_path));
            }
        }

        // Test-specific TOML (if provided)
        if let Some(path) = test_config_path {
            if path.exists() {
                figment = figment.merge(Toml::file(path));
            }
        }

        // Environment variables
        figment = figment.merge(
            Env::prefixed("CLNRM_WEAVER_")
                .split("_")
                .map(|key| key.as_str().to_lowercase().into())
        );

        // CLI overrides (highest precedence)
        if let Some(cli) = cli_overrides {
            figment = figment.merge(Serialized::defaults(cli));
        }

        let config: WeaverConfig = figment.extract()
            .map_err(|e| CleanroomError::config_error(format!("Config load failed: {}", e)))?;

        config.validate()?;
        Ok(config)
    }

    /// Validate configuration for consistency and correctness
    pub fn validate(&self) -> Result<()> {
        // Port validation
        if self.otlp_port > 0 && self.otlp_port < 1024 {
            return Err(CleanroomError::validation_error(
                "OTLP port must be >= 1024 or 0 for auto-discovery",
            ));
        }

        if self.admin_port > 0 && self.admin_port < 1024 {
            return Err(CleanroomError::validation_error(
                "Admin port must be >= 1024 or 0 for auto-discovery",
            ));
        }

        if self.otlp_port == self.admin_port && self.otlp_port > 0 {
            return Err(CleanroomError::validation_error(
                "OTLP port and admin port must be different",
            ));
        }

        // Nested validation
        if let Some(ref validation) = self.validation {
            validation.validate()?;
        }

        if let Some(ref eighty_twenty) = self.eighty_twenty {
            eighty_twenty.validate()?;
        }

        // Cross-field validation
        if let Some(ref validation) = self.validation {
            if validation.mode == ValidationMode::EightyTwenty && self.eighty_twenty.is_none() {
                return Err(CleanroomError::validation_error(
                    "80/20 validation mode requires [weaver.80_20] section with critical_spans and required_attributes",
                ));
            }
        }

        if let Some(ref collector) = self.collector {
            collector.validate()?;
        }

        Ok(())
    }
}
```
