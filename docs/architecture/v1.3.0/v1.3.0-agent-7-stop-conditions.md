## Executive Summary

This document defines the comprehensive architecture for handling all stop conditions in the Weaver live-check integration. The design ensures graceful shutdown, proper telemetry flushing, and predictable exit codes for CI/CD automation, while handling all four Weaver-supported stop triggers: SIGINT, SIGHUP, HTTP /stop endpoint, and inactivity timeout.

**Critical Principle:** Stop conditions must guarantee all telemetry is flushed and validated before exit. Premature shutdown = lost validation data = false negatives.

## Stop Condition Types

### 1. SIGINT (User Interrupt)

**Trigger:** User presses Ctrl+C in terminal

**Use Case:**
- Developer wants to stop test run early
- CI/CD timeout cancels job
- User realizes test configuration is wrong

**Behavior:**
```rust
// Signal received by clnrm main process
SIGINT → StopCoordinator::handle_sigint()
      → Begin graceful shutdown
      → Flush OTLP
      → Send SIGHUP to Weaver
      → Wait for report
      → Exit with code 130 (128 + 2)
```

**Requirements:**
- Must flush all in-flight telemetry before exit
- Must wait for Weaver to write final report
- Exit code 130 indicates SIGINT termination
- Timeout: 15 seconds total for graceful shutdown
- Force kill if timeout exceeded

---

### 2. SIGHUP (Hangup Signal)

**Trigger:** Process receives HUP signal (typically from parent process termination)

**Use Case:**
- Parent shell exits (terminal closed)
- SSH session disconnected
- Systemd/supervisor sends HUP on config reload

**Behavior:**
```rust
// Signal received by clnrm main process
SIGHUP → StopCoordinator::handle_sighup()
       → Begin graceful shutdown (same as SIGINT)
       → Exit with code 129 (128 + 1)
```

**Requirements:**
- Identical shutdown sequence to SIGINT
- Different exit code for differentiation
- Must be reentrant (multiple SIGHUPs possible)

---

### 3. HTTP /stop Endpoint

**Trigger:** HTTP GET request to `http://localhost:{admin_port}/stop`

**Use Case:**
- Automated orchestration tools
- Remote shutdown via admin API
- CI/CD workflows with external control
- Kubernetes pod termination hooks

**Behavior:**
```rust
// HTTP request handled by Weaver's admin server
GET /stop → Weaver admin server
          → Weaver graceful shutdown
          → Write validation report
          → Exit with code 0 (normal shutdown)

// clnrm detects Weaver exit
WeaverController::wait_for_exit()
                → Parse report
                → Exit with validation status
```

**Requirements:**
- Admin server must start with Weaver process
- Endpoint should return 200 OK before shutting down
- Response body: `{"status": "stopping", "message": "Graceful shutdown initiated"}`
- Idempotent: multiple /stop requests handled gracefully
- Authentication: optional (default: no auth for localhost)

**TOML Configuration:**
```toml
[test.live_check.stop]
enable_http_stop = true
http_stop_port = 0  # 0 = auto-discover from Weaver's --admin-port
```

---

### 4. Inactivity Timeout

**Trigger:** No telemetry received for N seconds (default: 10 seconds)

**Use Case:**
- Tests finish executing, no more telemetry expected
- Automatic shutdown after test completion
- Prevents hanging validation processes
- CI/CD resource efficiency

**Behavior:**
```rust
// Weaver monitors telemetry stream
No telemetry for 10s → Weaver inactivity timer expires
                     → Weaver graceful shutdown
                     → Write validation report
                     → Exit with code 0

// clnrm detects Weaver exit
WeaverController::wait_for_exit()
                → Parse report
                → Exit with validation status
```

**Requirements:**
- Configurable timeout duration (default: 10 seconds)
- Reset timer on each telemetry sample received
- Must flush all buffers before timeout triggers
- Warning log at 50% of timeout (5 seconds)

**TOML Configuration:**
```toml
[test.live_check.stop]
inactivity_timeout = 10  # seconds
```

**Edge Cases:**
- Very slow tests: Increase timeout to match test duration
- Streaming tests: Disable inactivity timeout (set to 0)
- Batch tests: Default timeout works (tests finish, then timeout)

## Graceful Shutdown Sequence

### Detailed Phase Breakdown

#### Phase 1: Stop Accepting New Telemetry (50ms target)

**Objectives:**
- Prevent new test execution from starting
- Set shutdown flag to reject new OTLP connections
- Allow in-flight requests to complete

**Implementation:**
```rust
impl StopCoordinator {
    fn phase_1_stop_accepting(&self) -> Result<()> {
        info!("🛑 Phase 1: Stopping new telemetry acceptance");

        // Set atomic shutdown flag
        self.shutdown_initiated.store(true, Ordering::SeqCst);

        // Signal test executor to stop
        if let Some(executor) = &self.test_executor {
            executor.cancel_remaining_tests()?;
        }

        // Note: We don't stop OTLP receiver here - let it drain buffers

        Ok(())
    }
}
```

**Success Criteria:**
- Shutdown flag set
- No new tests start
- In-flight tests allowed to complete (with timeout)

---

#### Phase 2: Flush OTLP Buffers (5s timeout)

**Objectives:**
- Force OTEL SDK to export all buffered spans
- Wait for batch exporters to complete
- Ensure no telemetry lost in buffers

**Implementation:**
```rust
impl StopCoordinator {
    fn phase_2_flush_otlp(&self) -> Result<()> {
        info!("📤 Phase 2: Flushing OTLP buffers");

        let flush_timeout = self.config.graceful_timeout;
        let start = Instant::now();

        // Drop OTEL guard to trigger flush
        if let Some(otel_guard) = self.otel_guard.take() {
            drop(otel_guard);

            // Wait for exporters to flush (blocking)
            // OTEL SDK's drop implementation handles this internally
            thread::sleep(Duration::from_millis(500));

            // Check if flush completed
            if start.elapsed() > flush_timeout {
                warn!("⚠️  OTLP flush timeout exceeded");
                return Err(CleanroomError::timeout_error(
                    "OTLP flush did not complete within timeout"
                ));
            }
        }

        let elapsed = start.elapsed();
        info!("✅ OTLP buffers flushed ({}ms)", elapsed.as_millis());
        Ok(())
    }
}
```

**Success Criteria:**
- OTEL guard dropped
- All buffered spans exported
- No export errors
- Completed within 5 seconds

**Failure Handling:**
- If timeout: Log warning, continue to next phase
- If export error: Log error, continue (validation will show missing spans)
- Non-blocking: Don't block shutdown on export failures

---

#### Phase 3: Signal Weaver to Stop (10s timeout)

**Objectives:**
- Send SIGHUP to Weaver process for graceful shutdown
- Wait for Weaver to acknowledge and begin shutdown
- Force kill if Weaver doesn't respond

**Implementation:**
```rust
impl StopCoordinator {
    fn phase_3_signal_weaver(&mut self) -> Result<()> {
        info!("📡 Phase 3: Signaling Weaver to stop");

        let weaver_timeout = self.config.force_kill_timeout;
        let start = Instant::now();

        // Send SIGHUP to Weaver
        if let Some(ref mut weaver_process) = self.weaver_controller.live_check_process {
            #[cfg(unix)]
            {
                use nix::sys::signal::{kill, Signal};
                use nix::unistd::Pid;

                let pid = Pid::from_raw(weaver_process.id() as i32);
                debug!("Sending SIGHUP to Weaver (PID: {})", pid);

                kill(pid, Signal::SIGHUP).map_err(|e| {
                    CleanroomError::internal_error(format!(
                        "Failed to send SIGHUP to Weaver: {}", e
                    ))
                })?;
            }

            #[cfg(not(unix))]
            {
                // On Windows, gracefully terminate via HTTP /stop
                self.send_http_stop()?;
            }

            // Wait for Weaver to exit gracefully
            loop {
                match weaver_process.try_wait() {
                    Ok(Some(_status)) => {
                        let elapsed = start.elapsed();
                        info!("✅ Weaver stopped gracefully ({}ms)", elapsed.as_millis());
                        return Ok(());
                    }
                    Ok(None) => {
                        // Still running
                        if start.elapsed() > weaver_timeout {
                            warn!("⚠️  Weaver did not stop gracefully, force killing");
                            weaver_process.kill()?;
                            return Err(CleanroomError::timeout_error(
                                "Weaver force killed after timeout"
                            ));
                        }
                        thread::sleep(Duration::from_millis(100));
                    }
                    Err(e) => {
                        return Err(CleanroomError::internal_error(format!(
                            "Failed to check Weaver status: {}", e
                        )));
                    }
                }
            }
        }

        Ok(())
    }

    #[cfg(not(unix))]
    fn send_http_stop(&self) -> Result<()> {
        let admin_port = self.weaver_controller.get_admin_port();
        let url = format!("http://localhost:{}/stop", admin_port);

        let client = reqwest::blocking::Client::builder()
            .timeout(Duration::from_secs(2))
            .build()?;

        client.get(&url).send()?;
        Ok(())
    }
}
```

**Success Criteria:**
- SIGHUP delivered successfully
- Weaver exits within timeout
- Exit status indicates normal termination

**Failure Handling:**
- If SIGHUP fails: Try HTTP /stop endpoint
- If timeout: Send SIGKILL and continue
- If SIGKILL fails: Log error, continue to cleanup

#### Phase 4: Collect Validation Report (2s timeout)

**Objectives:**
- Wait for Weaver to write validation_report.json
- Parse and validate JSON structure
- Handle missing or corrupt reports

**Implementation:**
```rust
impl StopCoordinator {
    fn phase_4_collect_report(&self) -> Result<ValidationReport> {
        info!("📊 Phase 4: Collecting validation report");

        let report_path = self.config.output_dir.join("validation_report.json");
        let timeout = Duration::from_secs(2);
        let start = Instant::now();

        // Poll for report file (Weaver writes on shutdown)
        loop {
            if report_path.exists() {
                // Wait a bit for file to be fully written
                thread::sleep(Duration::from_millis(100));

                let report_json = std::fs::read_to_string(&report_path)?;
                let report: ValidationReport = serde_json::from_str(&report_json)?;

                let elapsed = start.elapsed();
                info!("✅ Validation report collected ({}ms)", elapsed.as_millis());

                return Ok(report);
            }

            if start.elapsed() > timeout {
                warn!("⚠️  Validation report not found within timeout");
                return Ok(ValidationReport::default());
            }

            thread::sleep(Duration::from_millis(50));
        }
    }
}
```

**Success Criteria:**
- Report file exists
- Valid JSON structure
- Parsed successfully

**Failure Handling:**
- If file missing: Return default report (status: Failure)
- If JSON invalid: Log error, return default report
- If timeout: Return default report

#### Phase 5: Cleanup Resources (1s target)

**Objectives:**
- Close HTTP admin server (if running)
- Cleanup temporary files
- Release ports
- Stop background threads

**Implementation:**
```rust
impl StopCoordinator {
    fn phase_5_cleanup(&mut self) -> Result<()> {
        info!("🧹 Phase 5: Cleaning up resources");

        // Stop HTTP admin server
        if let Some(server) = self.http_stop_server.take() {
            server.shutdown()?;
        }

        // Stop inactivity monitor
        if let Some(monitor) = self.inactivity_monitor.take() {
            monitor.stop()?;
        }

        // Wait for background threads
        for handle in self.thread_handles.drain(..) {
            let _ = handle.join();
        }

        // Cleanup temp files (optional)
        if self.config.cleanup_temp_files {
            let _ = std::fs::remove_dir_all(&self.config.output_dir);
        }

        info!("✅ Resources cleaned up");
        Ok(())
    }
}
```

**Success Criteria:**
- All servers stopped
- All threads joined
- No resource leaks

**Failure Handling:**
- Best-effort cleanup
- Log warnings for failures
- Continue to exit even if cleanup fails

#### Phase 6: Exit with Appropriate Code

**Objectives:**
- Determine exit code based on validation results
- Ensure exit code reflects true validation state
- Provide clear logs for debugging

**Implementation:**
```rust
impl StopCoordinator {
    fn phase_6_exit(&self, report: ValidationReport) -> ! {
        info!("🏁 Phase 6: Exiting with validation status");

        let exit_code = match (self.shutdown_reason, report.status) {
            // Normal completion with violations
            (ShutdownReason::InactivityTimeout, ValidationStatus::Failure) => {
                error!("❌ Validation FAILED: {} violations", report.violations);
                1
            }
            // Normal completion without violations
            (ShutdownReason::InactivityTimeout, ValidationStatus::Success) => {
                info!("✅ Validation PASSED: No violations");
                0
            }
            // User interrupt (regardless of validation)
            (ShutdownReason::Sigint, _) => {
                warn!("⚠️  Interrupted by user (SIGINT)");
                130
            }
            // Hangup signal
            (ShutdownReason::Sighup, _) => {
                warn!("⚠️  Terminated by hangup (SIGHUP)");
                129
            }
            // HTTP stop (graceful, check validation)
            (ShutdownReason::HttpStop, ValidationStatus::Failure) => {
                error!("❌ Validation FAILED: {} violations", report.violations);
                1
            }
            (ShutdownReason::HttpStop, ValidationStatus::Success) => {
                info!("✅ Validation PASSED: No violations");
                0
            }
            // Force killed (infrastructure failure)
            (ShutdownReason::ForceKilled, _) => {
                error!("💀 Force killed after timeout");
                124
            }
            // Infrastructure error (Weaver crashed, etc.)
            (ShutdownReason::InfrastructureError, _) => {
                error!("🔥 Infrastructure error during validation");
                2
            }
        };

        info!("Exit code: {}", exit_code);
        std::process::exit(exit_code);
    }
}

#[derive(Debug, Clone, Copy)]
enum ShutdownReason {
    Sigint,
    Sighup,
    HttpStop,
    InactivityTimeout,
    ForceKilled,
    InfrastructureError,
}
```

**Exit Code Mapping:**
- 0: Success (conformance passed)
- 1: Conformance violations detected
- 2: Infrastructure failure (Weaver crashed, OTLP export failed)
- 124: Force killed (timeout exceeded)
- 129: SIGHUP termination
- 130: SIGINT termination

## Signal Handler Design

### Unix Signal Handling

**Objective:** Register signal handlers that safely coordinate shutdown from any thread.

**Implementation Strategy:**

```rust
use tokio::signal::unix::{signal, SignalKind};
use std::sync::Arc;

pub struct SignalHandler {
    shutdown_tx: mpsc::Sender<ShutdownReason>,
}

impl SignalHandler {
    pub fn new(shutdown_tx: mpsc::Sender<ShutdownReason>) -> Self {
        Self { shutdown_tx }
    }

    /// Install signal handlers (must be called in async context)
    pub async fn install_handlers(&self) -> Result<()> {
        // SIGINT handler (Ctrl+C)
        let mut sigint = signal(SignalKind::interrupt())?;
        let tx = self.shutdown_tx.clone();
        tokio::spawn(async move {
            sigint.recv().await;
            warn!("Received SIGINT, initiating graceful shutdown");
            let _ = tx.send(ShutdownReason::Sigint).await;
        });

        // SIGHUP handler (Hangup)
        let mut sighup = signal(SignalKind::hangup())?;
        let tx = self.shutdown_tx.clone();
        tokio::spawn(async move {
            sighup.recv().await;
            warn!("Received SIGHUP, initiating graceful shutdown");
            let _ = tx.send(ShutdownReason::Sighup).await;
        });

        // SIGTERM handler (Graceful termination)
        let mut sigterm = signal(SignalKind::terminate())?;
        let tx = self.shutdown_tx.clone();
        tokio::spawn(async move {
            sigterm.recv().await;
            warn!("Received SIGTERM, initiating graceful shutdown");
            let _ = tx.send(ShutdownReason::HttpStop).await;
        });

        info!("✅ Signal handlers installed");
        Ok(())
    }
}
```

**Safety Considerations:**
- Signal handlers use async channels (thread-safe)
- No blocking operations in signal handlers
- Shutdown coordination via message passing
- Reentrant: Multiple signals handled gracefully

### Windows Signal Handling

**Objective:** Provide equivalent behavior on Windows (limited signal support).

**Implementation Strategy:**

```rust
#[cfg(windows)]
pub struct SignalHandler {
    shutdown_tx: mpsc::Sender<ShutdownReason>,
}

#[cfg(windows)]
impl SignalHandler {
    pub async fn install_handlers(&self) -> Result<()> {
        // Windows only supports Ctrl+C (SIGINT equivalent)
        let tx = self.shutdown_tx.clone();

        tokio::spawn(async move {
            tokio::signal::ctrl_c().await.expect("Failed to install Ctrl+C handler");
            warn!("Received Ctrl+C, initiating graceful shutdown");
            let _ = tx.send(ShutdownReason::Sigint).await;
        });

        info!("✅ Signal handlers installed (Windows)");
        Ok(())
    }
}
```

**Limitations:**
- Windows only supports Ctrl+C (SIGINT)
- No SIGHUP equivalent
- Use HTTP /stop endpoint for programmatic shutdown on Windows

---

### Signal Propagation

**Objective:** Propagate signals from clnrm to Weaver process.

**Flow:**
```
User presses Ctrl+C
  → clnrm receives SIGINT
  → clnrm begins graceful shutdown
  → clnrm sends SIGHUP to Weaver (NOT SIGINT)
  → Weaver receives SIGHUP
  → Weaver graceful shutdown
  → Weaver writes validation report
  → clnrm waits for report
  → clnrm exits with code 130
```

**Why SIGHUP and not SIGINT?**
- SIGINT may have default handler that kills immediately
- SIGHUP is explicitly for graceful shutdown
- Weaver documentation specifies SIGHUP for graceful stop
- Prevents race conditions with default signal handlers

## Inactivity Detection

### Telemetry Stream Monitoring

**Objective:** Automatically stop validation when no more telemetry is expected.

**Mechanism:**
- Weaver monitors OTLP stream for incoming samples
- Starts inactivity timer on initialization
- Resets timer on each sample received
- Triggers shutdown when timer expires

**Weaver CLI Flag:**
```bash
weaver registry live-check \
  --inactivity-timeout 10  # seconds (default: 10)
```

**TOML Configuration:**
```toml
[test.live_check.stop]
inactivity_timeout = 10  # seconds
```

---

### Timeout Calculation Strategy

**Default Timeout:** 10 seconds

**Adaptive Timeout (Future Enhancement):**
```rust
fn calculate_inactivity_timeout(test_count: usize, avg_test_duration: Duration) -> u32 {
    // Heuristic: 2x average test duration or 10s minimum
    let estimated = (avg_test_duration.as_secs() * 2) as u32;
    std::cmp::max(estimated, 10)
}
```

**Edge Cases:**
- **Slow tests:** User must manually increase timeout
- **Streaming tests:** Set timeout to 0 (disabled)
- **Batch tests:** Default timeout works well

### False Positive Prevention

**Problem:** Timer expires during legitimate pause in telemetry

**Solutions:**

1. **Warning Logs:**
```rust
// At 50% of timeout
warn!("No telemetry received for {}s ({}s until timeout)",
      timeout / 2, timeout / 2);
```

2. **Heartbeat Mechanism (Future):**
```rust
// clnrm sends periodic heartbeat to Weaver
tokio::spawn(async move {
    loop {
        send_heartbeat_span().await;
        tokio::time::sleep(Duration::from_secs(5)).await;
    }
});
```

3. **User Override:**
```toml
[test.live_check.stop]
inactivity_timeout = 0  # Disable timeout, manual stop only
```

## Exit Code Strategy

### Exit Code Definitions

| Code | Meaning | Use Case | CI/CD Action |
|------|---------|----------|--------------|
| 0 | Success | Validation passed, no violations | Proceed to deploy |
| 1 | Validation Failed | Conformance violations detected | Block deployment |
| 2 | Infrastructure Error | Weaver crashed, OTLP export failed | Alert ops team |
| 124 | Force Killed | Timeout exceeded, forced termination | Investigate timeout |
| 129 | SIGHUP | Terminated by hangup signal | Retry with nohup |
| 130 | SIGINT | Interrupted by user (Ctrl+C) | No action |

---

### Exit Code Determination Logic

```rust
fn determine_exit_code(
    reason: ShutdownReason,
    report: ValidationReport,
    infrastructure_ok: bool,
) -> i32 {
    match (reason, infrastructure_ok, report.status) {
        // Infrastructure failure overrides everything
        (_, false, _) => 2,

        // Force killed overrides validation
        (ShutdownReason::ForceKilled, _, _) => 124,

        // User interrupt
        (ShutdownReason::Sigint, _, _) => 130,
        (ShutdownReason::Sighup, _, _) => 129,

        // Normal completion - check validation
        (_, true, ValidationStatus::Success) => 0,
        (_, true, ValidationStatus::Failure) => 1,
    }
}
```

## Error Handling

### Error Categories

1. **Recoverable Errors:** Log warning, continue shutdown
2. **Critical Errors:** Abort graceful shutdown, force kill
3. **Infrastructure Errors:** Exit with code 2

---

### Error Scenarios

#### Scenario 1: Weaver Process Unresponsive

**Symptoms:**
- SIGHUP sent but Weaver doesn't exit
- Timeout waiting for graceful shutdown

**Handling:**
```rust
// After 10 seconds of waiting
if start.elapsed() > force_kill_timeout {
    warn!("Weaver unresponsive, sending SIGKILL");

    #[cfg(unix)]
    {
        use nix::sys::signal::{kill, Signal};
        kill(pid, Signal::SIGKILL)?;
    }

    #[cfg(not(unix))]
    {
        process.kill()?;
    }

    // Mark as force killed
    shutdown_reason = ShutdownReason::ForceKilled;
}
```

**Exit Code:** 124 (force killed)

---

#### Scenario 2: OTLP Flush Timeout

**Symptoms:**
- OTEL exporters don't flush within timeout
- Telemetry lost in buffers

**Handling:**
```rust
if flush_start.elapsed() > otlp_flush_timeout {
    warn!("⚠️  OTLP flush timeout - some telemetry may be lost");
    // Continue to next phase
    // Validation report will show missing spans as violations
}
```

**Exit Code:** 1 (validation will fail due to missing spans)

---

#### Scenario 3: Report Parsing Failure

**Symptoms:**
- validation_report.json doesn't exist
- JSON is malformed or corrupt

**Handling:**
```rust
let report = match parse_validation_report(&report_path) {
    Ok(report) => report,
    Err(e) => {
        error!("Failed to parse validation report: {}", e);
        error!("Assuming validation failed");

        ValidationReport {
            status: ValidationStatus::Failure,
            violations: u32::MAX,  // Unknown violation count
            message: format!("Report parsing failed: {}", e),
            ..Default::default()
        }
    }
};
```

**Exit Code:** 2 (infrastructure error - report should always exist)

---

#### Scenario 4: Multiple Stop Triggers

**Symptoms:**
- User presses Ctrl+C while HTTP /stop request pending
- Multiple shutdown triggers race

**Handling:**
```rust
impl StopCoordinator {
    fn handle_shutdown_trigger(&mut self, reason: ShutdownReason) -> Result<()> {
        // Use atomic CAS to ensure only one shutdown
        if self.shutdown_initiated.compare_exchange(
            false,
            true,
            Ordering::SeqCst,
            Ordering::SeqCst,
        ).is_err() {
            warn!("Shutdown already initiated, ignoring duplicate trigger");
            return Ok(());
        }

        self.shutdown_reason = Some(reason);
        self.execute_graceful_shutdown()?;
        Ok(())
    }
}
```

**Behavior:** First trigger wins, subsequent triggers ignored

---

#### Scenario 5: Signal Delivery Failure

**Symptoms:**
- kill() returns ESRCH (no such process)
- Weaver process already exited

**Handling:**
```rust

    Ok(()) => {
        debug!("SIGHUP sent successfully");
    }
    Err(nix::errno::Errno::ESRCH) => {
        warn!("Weaver already exited, skipping signal");
        // Continue to report collection

        return Err(CleanroomError::internal_error(format!(
            "Failed to send SIGHUP: {}", e
        )));
    }
}
```

**Behavior:** Continue to report collection if process already exited

## Implementation Guide

### Core Components

#### 1. StopCoordinator

```rust
pub struct StopCoordinator {
    config: StopConfig,
    shutdown_initiated: Arc<AtomicBool>,
    shutdown_reason: Option<ShutdownReason>,
    weaver_controller: WeaverController,
    otel_guard: Option<OtelGuard>,
    signal_handler: SignalHandler,
    http_stop_server: Option<HttpStopServer>,
    inactivity_monitor: Option<InactivityMonitor>,
    shutdown_tx: mpsc::Sender<ShutdownReason>,
    shutdown_rx: mpsc::Receiver<ShutdownReason>,
}

impl StopCoordinator {
    pub fn new(config: StopConfig, weaver: WeaverController) -> Self {
        let (tx, rx) = mpsc::channel(10);

        Self {
            config,
            shutdown_initiated: Arc::new(AtomicBool::new(false)),
            shutdown_reason: None,
            weaver_controller: weaver,
            otel_guard: None,
            signal_handler: SignalHandler::new(tx.clone()),
            http_stop_server: None,
            inactivity_monitor: None,
            shutdown_tx: tx,
            shutdown_rx: rx,
        }
    }

    pub async fn run(&mut self) -> Result<i32> {
        // Install signal handlers
        self.signal_handler.install_handlers().await?;

        // Wait for shutdown trigger
        let reason = self.shutdown_rx.recv().await
            .ok_or_else(|| CleanroomError::internal_error("Shutdown channel closed"))?;

        info!("Shutdown triggered: {:?}", reason);
        self.shutdown_reason = Some(reason);

        // Execute graceful shutdown
        match self.execute_graceful_shutdown() {
            Ok(report) => {
                Ok(self.determine_exit_code(report))
            }
            Err(e) => {
                error!("Graceful shutdown failed: {}", e);
                Ok(2)  // Infrastructure error
            }
        }
    }

    fn execute_graceful_shutdown(&mut self) -> Result<ValidationReport> {
        info!("🛑 Beginning graceful shutdown sequence");

        let start = Instant::now();

        // Phase 1: Stop accepting new telemetry
        self.phase_1_stop_accepting()?;

        // Phase 2: Flush OTLP buffers
        self.phase_2_flush_otlp()?;

        // Phase 3: Signal Weaver to stop
        self.phase_3_signal_weaver()?;

        // Phase 4: Collect validation report
        let report = self.phase_4_collect_report()?;

        // Phase 5: Cleanup resources
        self.phase_5_cleanup()?;

        let elapsed = start.elapsed();
        info!("✅ Graceful shutdown complete ({}ms)", elapsed.as_millis());

        Ok(report)
    }

    fn determine_exit_code(&self, report: ValidationReport) -> i32 {
        determine_exit_code(
            self.shutdown_reason.unwrap(),
            report,
            true,  // infrastructure_ok
        )
    }
}
```

    coordinator.set_otel_guard(otel_guard);

    // Run tests in background
    let test_handle = tokio::spawn(async move {
        run_tests().await
    });

    // Wait for shutdown trigger or test completion
    tokio::select! {
        exit_code = coordinator.run() => {
            info!("Coordinator returned exit code: {}", exit_code?);
            std::process::exit(exit_code?);
        }
        test_result = test_handle => {
            // Tests completed naturally, trigger inactivity timeout
            coordinator.trigger_shutdown(ShutdownReason::InactivityTimeout).await;
        }
    }

    Ok(())
}
