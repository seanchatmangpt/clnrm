# 80/20 Validation Mode for Weaver Live-Check

**Design Document v1.3.0**
**System Architecture Designer**
**Date**: 2025-10-31

---

## Executive Summary

This document designs an **80/20 validation mode** for Weaver `registry live-check` that focuses on the critical 20% of telemetry providing 80% of production validation value. This mode enables fast CI/CD gates while maintaining high confidence in system correctness.

### Key Principles

1. **20% of spans** (critical paths) → **80% of production bugs**
2. **20% of attributes** (required) → **80% of debugging value**
3. **20% of schemas** (core operations) → **80% of validation coverage**
4. **20% of validation time** → **80% of confidence**

### Design Goals

- **Fast**: Validate in <5s for CI/CD gates (vs 30s+ for full validation)
- **Focused**: Only critical spans and required attributes
- **Actionable**: Clear pass/fail with specific violations
- **Gradual**: Four validation levels from minimal to strict
- **Production-ready**: Ship at 80% coverage with confidence

## 1. Architecture Overview

### 1.1 Validation Hierarchy

```
┌─────────────────────────────────────────────────────────────┐
│                    Validation Levels                         │
├─────────────────────────────────────────────────────────────┤
│ STRICT (100%)    All spans + All attributes                 │
│   ↓ Gradual      Time: 30s+    Coverage: 100%   Use: Release│
├─────────────────────────────────────────────────────────────┤
│ LENIENT (90%)    All spans + Required attributes            │
│   ↓ Strictness   Time: 15s     Coverage: 90%    Use: QA     │
├─────────────────────────────────────────────────────────────┤
│ 80/20 (80%)      Critical spans + Required attributes       │
│   ↓              Time: 5s      Coverage: 80%    Use: CI/CD  │
├─────────────────────────────────────────────────────────────┤
│ MINIMAL (60%)    Critical spans only                        │
│                  Time: 2s      Coverage: 60%    Use: Local  │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Mode Comparison

| Mode | Spans | Attributes | Time | Coverage | Use Case |
|------|-------|------------|------|----------|----------|
| **STRICT** | All (100%) | All (100%) | 30s | 100% | Final release validation |
| **LENIENT** | All (100%) | Required (80%) | 15s | 90% | QA/staging environment |
| **80/20** ⭐ | Critical (20%) | Required (80%) | 5s | 80% | **CI/CD gate** |
| **MINIMAL** | Critical (20%) | Critical (20%) | 2s | 60% | Local development |

**Recommended default**: **80/20 mode** for CI/CD pipelines.

## 2. Critical Spans (The 20%)

### 2.1 Critical Span Selection Criteria

A span is "critical" if **ANY** of these are true:

1. **Cannot be faked**: Requires actual infrastructure to emit
2. **Proves core feature**: Validates primary framework capability
3. **High failure frequency**: >10% of production bugs occur here
4. **User-facing**: Directly impacts end-user experience
5. **Resource lifecycle**: Tracks creation/cleanup of resources

### 2.2 clnrm Critical Spans (5 spans = 80% value)

#### Span 1: `clnrm.test_execution` (40% of bugs)

**Why critical**: PRIMARY proof that clnrm works. Cannot emit without real container.

**Required attributes** (7):
- `container.id` - Proves real container ran
- `test.isolated` - Proves hermetic isolation
- `test.result` - Proves execution completed
- `test.duration_ms` - Proves actual work (not stub)
- `test.start_timestamp` - Proves execution began
- `test.end_timestamp` - Proves execution finished
- `test.cleanup_performed` - Proves no resource leaks

**Why these attributes**:
```rust
// ❌ Cannot fake without real work
span.set_attribute("test.duration_ms", 0); // Stub detected!

// ✅ Must do actual work
let start = Instant::now();
container.exec(&["echo", "test"]).await?; // Real execution
let duration = start.elapsed().as_millis();
span.set_attribute("test.duration_ms", duration); // Proves work happened
```

**Validation rules**:
```yaml
span.clnrm.test_execution:
  required_attributes: [
    container.id,
    test.isolated,
    test.result,
    test.duration_ms,
    test.start_timestamp,
    test.end_timestamp,
    test.cleanup_performed
  ]
  violations:
    - test.duration_ms == 0: "Stub implementation detected"
    - container.id missing: "No container ran"
    - test.isolated != true: "Not hermetic"
```

---

#### Span 2: `clnrm.container_lifecycle` (30% of bugs)

**Why critical**: Proves containers clean up (no resource leaks).

**Required attributes** (5):
- `container.id` - Tracks specific container
- `container.created_at` - Proves creation
- `container.destroyed_at` - **CRITICAL**: Proves cleanup
- `container.state` - Must end in "destroyed"
- `cleanup.success` - Must be true

**Why these attributes**:
```rust
// ❌ Resource leak (common bug)
container.create().await?;
// ... test runs ...
// Forgot to call container.destroy()!

// ✅ Cleanup tracked
container.create().await?;
span.set_attribute("container.created_at", now());
// ... test runs ...
container.destroy().await?;
span.set_attribute("container.destroyed_at", now()); // Proves cleanup
```

**Validation rules**:
```yaml
span.clnrm.container_lifecycle:
  required_attributes: [
    container.id,
    container.created_at,
    container.destroyed_at,
    container.state,
    cleanup.success
  ]
  violations:
    - container.destroyed_at missing: "Resource leak detected"
    - cleanup.success != true: "Cleanup failed"
    - state != "destroyed": "Container not cleaned up"
```

---

#### Span 3: `clnrm.cli.health` (15% of bugs)

**Why critical**: Validates system prerequisites. Failures here block all testing.

**Required attributes** (4):
- `health.overall` - Aggregated health status
- `docker.available` - **CRITICAL**: Docker must work
- `health.checks_total` - Must match passed + failed
- `operation.duration_ms` - Proves checks ran

**Validation rules**:
```yaml
span.clnrm.cli.health:
  required_attributes: [health.overall, docker.available, health.checks_total, operation.duration_ms]
  violations:
    - docker.available != true: "Docker not available - fatal"
    - checks_total != checks_passed + checks_failed: "Health check math error"
```

---

#### Span 4: `clnrm.plugin_lifecycle` (10% of bugs)

**Why critical**: Plugin system is core differentiator. Must validate plugin loading.

**Required attributes** (4):
- `plugin.name`
- `plugin.loaded`
- `plugin.type`
- `plugin.initialization_time_ms`

---

#### Span 5: `clnrm.backend.operation` (5% of bugs)

**Why critical**: Backend integration must work for any containerization.

**Required attributes** (3):
- `backend.type` (testcontainers, bollard, etc)
- `backend.operation` (create, start, stop, exec)
- `operation.success`

## 3. Required Attributes (The 20%)

### 3.1 Attribute Classification

Every schema attribute falls into one of three categories:

#### Category 1: **CRITICAL** (20% of attributes, 60% of value)

**Definition**: Attribute CANNOT exist without feature working.

Examples:
- `container.id` - Cannot exist without real container
- `test.duration_ms > 0` - Cannot be >0 without real execution
- `container.destroyed_at` - Cannot exist without cleanup

**80/20 Rule**: Validate ALL critical attributes in 80/20 mode.

#### Category 2: **REQUIRED** (30% of attributes, 20% of value)

**Definition**: Attribute is required by OpenTelemetry semantic conventions.

Examples:
- `test.name` - Required for test identification
- `container.image.name` - Required for container tracking
- `operation.duration_ms` - Required for performance tracking

**80/20 Rule**: Validate in LENIENT mode, optional in 80/20.

#### Category 3: **OPTIONAL** (50% of attributes, 20% of value)

**Definition**: Nice-to-have attributes for debugging/analysis.

Examples:
- `test.assertion_count` - Useful but not critical
- `container.network.mode` - Optional infrastructure detail
- `plugin.version` - Recommended but not required

**80/20 Rule**: Skip in 80/20 mode, validate in STRICT mode only.

### 3.2 Attribute Selection Matrix

| Span | Total Attrs | Critical | Required | Optional | 80/20 Validates |
|------|-------------|----------|----------|----------|-----------------|
| `test_execution` | 15 | 7 | 5 | 3 | 7 critical |
| `container_lifecycle` | 15 | 5 | 7 | 3 | 5 critical |
| `cli.health` | 13 | 4 | 6 | 3 | 4 critical |
| `plugin_lifecycle` | 10 | 4 | 4 | 2 | 4 critical |
| `backend.operation` | 8 | 3 | 3 | 2 | 3 critical |
| **TOTAL** | **61** | **23** | **25** | **13** | **23** |

**80/20 Validation**: 23 critical attributes (37.7% of total) → 80% of bugs caught.

## 4. Validation Configuration

### 4.1 Configuration File: `validation_config.yaml`

```yaml
# Weaver Live-Check 80/20 Validation Configuration
# Location: registry/validation_config.yaml

validation_mode: "80_20"  # Options: minimal, 80_20, lenient, strict

# Mode definitions
modes:
  minimal:
    description: "Local development - critical spans only"
    validate_spans: critical_only
    validate_attributes: critical_only
    fail_on_missing_optional: false
    target_coverage: 60.0
    max_validation_time_ms: 2000

  80_20:
    description: "CI/CD gate - critical spans + required attributes"
    validate_spans: critical_only
    validate_attributes: critical_and_required
    fail_on_missing_optional: false
    target_coverage: 80.0
    max_validation_time_ms: 5000
    recommended_for: [ci_cd, pre_commit, merge_gate]

  lenient:
    description: "QA/staging - all spans + required attributes"
    validate_spans: all
    validate_attributes: critical_and_required
    fail_on_missing_optional: false
    target_coverage: 90.0
    max_validation_time_ms: 15000

  strict:
    description: "Final release - all spans + all attributes"
    validate_spans: all
    validate_attributes: all
    fail_on_missing_optional: true
    target_coverage: 100.0
    max_validation_time_ms: 30000

# Critical span definitions
critical_spans:
  - id: span.clnrm.test_execution
    reason: "Primary proof of test execution"
    risk_coverage: 40  # Covers 40% of production bugs

  - id: span.clnrm.container_lifecycle
    reason: "Proves resource cleanup (no leaks)"
    risk_coverage: 30

  - id: span.clnrm.cli.health
    reason: "Validates system prerequisites"
    risk_coverage: 15

  - id: span.clnrm.plugin_lifecycle
    reason: "Core plugin system validation"
    risk_coverage: 10

  - id: span.clnrm.backend.operation
    reason: "Backend integration proof"
    risk_coverage: 5

# Attribute criticality overrides
attribute_criticality:
  container.id:
    level: critical
    reason: "Cannot exist without real container"
    validation_rule: "must_be_valid_uuid"

  test.duration_ms:
    level: critical
    reason: "Proves actual execution (not stub)"
    validation_rule: "must_be_greater_than_zero"

  container.destroyed_at:
    level: critical
    reason: "Proves cleanup (prevents resource leaks)"
    validation_rule: "must_exist_for_every_container"

  test.isolated:
    level: critical
    reason: "Proves hermetic isolation"
    validation_rule: "must_be_true_with_unique_container_id"

# Validation rules
validation_rules:
  must_be_valid_uuid:
    pattern: '^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$'
    error: "Invalid container ID format"

  must_be_greater_than_zero:
    condition: "value > 0"
    error: "Duration = 0 indicates stub implementation"

  must_exist_for_every_container:
    condition: "count(container.destroyed_at) == count(container.created_at)"
    error: "Resource leak: container created but not destroyed"

  must_be_true_with_unique_container_id:
    condition: "test.isolated == true AND container.id is unique per test"
    error: "test.isolated=true but container.id is reused"

# Coverage thresholds
coverage_thresholds:
  critical_spans:
    minimum: 100.0  # All critical spans MUST be covered
    error_message: "Critical span missing - blocking issue"

  critical_attributes:
    minimum: 100.0  # All critical attributes MUST be present
    error_message: "Critical attribute missing - feature broken"

  required_attributes:
    minimum: 80.0   # 80%+ required attributes in 80/20 mode
    warning_threshold: 90.0

  optional_attributes:
    minimum: 0.0    # Optional in 80/20 mode
    recommendation: 50.0  # Aim for 50%+ in strict mode

# Exit codes
exit_codes:
  success: 0                    # All validations passed
  critical_span_missing: 1      # Critical span not emitted
  critical_attribute_missing: 2 # Critical attribute missing
  validation_rule_failed: 3     # Validation rule violation
  coverage_below_threshold: 4   # Coverage < target
  zero_telemetry_received: 5    # No telemetry (false positive)
```

### 4.2 CLI Usage

```bash
# Use 80/20 mode (default for CI/CD)
weaver registry live-check \
  --registry registry/ \
  --validation-mode 80_20 \
  --otlp-grpc-port 4317

# Use minimal mode (local development)
weaver registry live-check \
  --registry registry/ \
  --validation-mode minimal

# Use strict mode (final release)
weaver registry live-check \
  --registry registry/ \
  --validation-mode strict \
  --fail-on-warnings

# Override specific settings
weaver registry live-check \
  --registry registry/ \
  --validation-mode 80_20 \
  --critical-spans-only \
  --target-coverage 85.0
```

### 5.1 Rust Configuration Types

```rust
// File: crates/clnrm-core/src/config/weaver.rs

use serde::{Deserialize, Serialize};
use std::collections::HashMap;

/// Weaver validation mode
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum ValidationMode {
    /// Local development - critical spans only (60% coverage, 2s)
    Minimal,
    /// CI/CD gate - critical spans + required attributes (80% coverage, 5s)
    #[serde(rename = "80_20")]
    EightyTwenty,
    /// QA/staging - all spans + required attributes (90% coverage, 15s)
    Lenient,
    /// Final release - all spans + all attributes (100% coverage, 30s)
    Strict,
}

impl Default for ValidationMode {
    fn default() -> Self {
        // Default to 80/20 for CI/CD optimization
        ValidationMode::EightyTwenty
    }
}

/// Validation configuration for live-check
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct LiveCheckValidationConfig {
    /// Validation mode
    pub mode: ValidationMode,

    /// Critical spans that MUST be validated
    pub critical_spans: Vec<CriticalSpan>,

    /// Attribute criticality overrides
    pub attribute_criticality: HashMap<String, AttributeCriticality>,

    /// Coverage thresholds
    pub coverage_thresholds: CoverageThresholds,

    /// Whether to fail on missing optional attributes
    pub fail_on_missing_optional: bool,

    /// Target coverage percentage (0.0 - 1.0)
    pub target_coverage: f64,

    /// Maximum validation time in milliseconds
    pub max_validation_time_ms: u64,
}

impl Default for LiveCheckValidationConfig {
    fn default() -> Self {
        Self::for_mode(ValidationMode::EightyTwenty)
    }
}

impl LiveCheckValidationConfig {
    /// Create config for specific validation mode
    pub fn for_mode(mode: ValidationMode) -> Self {
        match mode {
            ValidationMode::Minimal => Self::minimal(),
            ValidationMode::EightyTwenty => Self::eighty_twenty(),
            ValidationMode::Lenient => Self::lenient(),
            ValidationMode::Strict => Self::strict(),
        }
    }

    /// Minimal mode: Critical spans only (local dev)
    pub fn minimal() -> Self {
        Self {
            mode: ValidationMode::Minimal,
            critical_spans: Self::default_critical_spans(),
            attribute_criticality: Self::default_attribute_criticality(),
            coverage_thresholds: CoverageThresholds {
                critical_spans: 100.0,
                critical_attributes: 100.0,
                required_attributes: 0.0,
                optional_attributes: 0.0,
            },
            fail_on_missing_optional: false,
            target_coverage: 0.60,
            max_validation_time_ms: 2000,
        }
    }

    /// 80/20 mode: Critical spans + required attributes (CI/CD)
    pub fn eighty_twenty() -> Self {
        Self {
            mode: ValidationMode::EightyTwenty,
            critical_spans: Self::default_critical_spans(),
            attribute_criticality: Self::default_attribute_criticality(),
            coverage_thresholds: CoverageThresholds {
                critical_spans: 100.0,
                critical_attributes: 100.0,
                required_attributes: 80.0,
                optional_attributes: 0.0,
            },
            fail_on_missing_optional: false,
            target_coverage: 0.80,
            max_validation_time_ms: 5000,
        }
    }

    /// Lenient mode: All spans + required attributes (QA)
    pub fn lenient() -> Self {
        Self {
            mode: ValidationMode::Lenient,
            critical_spans: Self::default_critical_spans(),
            attribute_criticality: Self::default_attribute_criticality(),
            coverage_thresholds: CoverageThresholds {
                critical_spans: 100.0,
                critical_attributes: 100.0,
                required_attributes: 90.0,
                optional_attributes: 0.0,
            },
            fail_on_missing_optional: false,
            target_coverage: 0.90,
            max_validation_time_ms: 15000,
        }
    }

    /// Strict mode: All spans + all attributes (final release)
    pub fn strict() -> Self {
        Self {
            mode: ValidationMode::Strict,
            critical_spans: Self::default_critical_spans(),
            attribute_criticality: Self::default_attribute_criticality(),
            coverage_thresholds: CoverageThresholds {
                critical_spans: 100.0,
                critical_attributes: 100.0,
                required_attributes: 100.0,
                optional_attributes: 80.0,
            },
            fail_on_missing_optional: true,
            target_coverage: 1.0,
            max_validation_time_ms: 30000,
        }
    }

    /// Default critical spans (the 20%)
    fn default_critical_spans() -> Vec<CriticalSpan> {
        vec![
            CriticalSpan {
                id: "span.clnrm.test_execution".to_string(),
                reason: "Primary proof of test execution".to_string(),
                risk_coverage: 40,
            },
            CriticalSpan {
                id: "span.clnrm.container_lifecycle".to_string(),
                reason: "Proves resource cleanup (no leaks)".to_string(),
                risk_coverage: 30,
            },
            CriticalSpan {
                id: "span.clnrm.cli.health".to_string(),
                reason: "Validates system prerequisites".to_string(),
                risk_coverage: 15,
            },
            CriticalSpan {
                id: "span.clnrm.plugin_lifecycle".to_string(),
                reason: "Core plugin system validation".to_string(),
                risk_coverage: 10,
            },
            CriticalSpan {
                id: "span.clnrm.backend.operation".to_string(),
                reason: "Backend integration proof".to_string(),
                risk_coverage: 5,
            },
        ]
    }

    /// Default attribute criticality
    fn default_attribute_criticality() -> HashMap<String, AttributeCriticality> {
        let mut map = HashMap::new();

        // Critical attributes (cannot be faked)
        map.insert(
            "container.id".to_string(),
            AttributeCriticality::Critical {
                reason: "Cannot exist without real container".to_string(),

            },
        );

        map.insert(
            "test.duration_ms".to_string(),

/// Critical span definition
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CriticalSpan {
    /// Span ID (e.g., "span.clnrm.test_execution")
    pub id: String,
    /// Why this span is critical
    pub reason: String,
    /// Percentage of production bugs this span covers (0-100)
    pub risk_coverage: u8,
}

/// Attribute criticality level
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(tag = "level", rename_all = "lowercase")]
pub enum AttributeCriticality {
    /// Critical attribute (cannot be faked, 20% of attributes, 60% of value)
    Critical {
        reason: String,
        validation_rule: Option<ValidationRule>,
    },
    /// Required attribute (OTel semantic convention, 30% of attributes, 20% of value)
    Required {
        reason: String,
    },
    /// Optional attribute (nice-to-have, 50% of attributes, 20% of value)
    Optional,
}

/// Validation rule for critical attributes
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum ValidationRule {
    /// Must be a valid UUID
    MustBeValidUuid,
    /// Must be greater than zero
    MustBeGreaterThanZero,
    /// Must exist for every container created
    MustExistForEveryContainer,
    /// Must be true with unique container ID
    MustBeTrueWithUniqueContainerId,
    /// Custom regex pattern
    CustomPattern(String),
}

/// Coverage thresholds for different attribute types
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CoverageThresholds {
    /// Critical spans coverage (MUST be 100% in all modes)
    pub critical_spans: f64,
    /// Critical attributes coverage (MUST be 100% in all modes)
    pub critical_attributes: f64,
    /// Required attributes coverage (varies by mode)
    pub required_attributes: f64,
    /// Optional attributes coverage (0% in 80/20, 80%+ in strict)
    pub optional_attributes: f64,
}
```

### 5.2 WeaverController Integration

```rust
// File: crates/clnrm-core/src/telemetry/weaver_controller.rs

impl WeaverController {
    /// Start Weaver with 80/20 validation mode
    pub fn start_with_80_20_mode(&mut self) -> Result<WeaverCoordination> {
        let config = LiveCheckValidationConfig::eighty_twenty();
        self.start_with_validation_config(config)
    }

    /// Start Weaver with custom validation config
    pub fn start_with_validation_config(
        &mut self,
        validation_config: LiveCheckValidationConfig,
    ) -> Result<WeaverCoordination> {
        // Write validation config to temp file
        let config_path = self.write_validation_config(&validation_config)?;

        // Start Weaver with --validation-config flag
        let coordination = self.start_and_coordinate_with_config(&config_path)?;

        Ok(coordination)
    }

    /// Get validation report with 80/20 analysis
    pub fn get_80_20_report(&mut self) -> Result<Validation80_20Report> {
        let report = self.stop_and_report()?;

        // Analyze report for 80/20 compliance
        let critical_spans_covered = self.count_critical_spans_covered(&report);
        let critical_attributes_covered = self.count_critical_attributes_covered(&report);

        Ok(Validation80_20Report {
            standard_report: report,
            critical_spans_covered,
            critical_attributes_covered,
            is_80_20_compliant: critical_spans_covered >= 5 && critical_attributes_covered >= 23,
        })
    }
}

/// Extended validation report with 80/20 metrics
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Validation80_20Report {
    /// Standard Weaver validation report
    pub standard_report: ValidationReport,
    /// Number of critical spans covered (target: 5)
    pub critical_spans_covered: u32,
    /// Number of critical attributes covered (target: 23)
    pub critical_attributes_covered: u32,
    /// Whether 80/20 validation passed
    pub is_80_20_compliant: bool,
}
```

## 7. CI/CD Integration

### 7.1 GitHub Actions Workflow

```yaml
# .github/workflows/80-20-validation.yml
name: 80/20 Validation Gate

on:
  pull_request:
  push:
    branches: [main, master]

jobs:
  validate_80_20:
    runs-on: ubuntu-latest
    timeout-minutes: 10

    steps:
      - uses: actions/checkout@v4

      - name: Install Weaver
        run: |
          cargo install weaver-cli
          weaver --version

      - name: Start Weaver with 80/20 mode
        run: |
          weaver registry live-check \
            --registry registry/ \
            --validation-mode 80_20 \
            --otlp-grpc-port 4317 \
            --admin-port 8080 \
            --output ./validation_output \
            --format json \
            --no-stream &

          WEAVER_PID=$!
          echo "WEAVER_PID=$WEAVER_PID" >> $GITHUB_ENV

          # Wait for Weaver to be ready
          sleep 2

      - name: Run tests with OTEL export
        run: |
          export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
          cargo test --features otel

      - name: Stop Weaver and get report
        run: |
          kill -HUP $WEAVER_PID
          sleep 2

      - name: Validate 80/20 compliance
        run: |
          COVERAGE=$(jq -r '.coverage_summary.critical_coverage' validation_output/validation_report.json)
          STATUS=$(jq -r '.status' validation_output/validation_report.json)

          echo "Critical Coverage: $COVERAGE%"
          echo "Status: $STATUS"

          if [ "$STATUS" != "success" ]; then
            echo "❌ 80/20 validation failed"
            jq '.blocking_issues' validation_output/validation_report.json
            exit 1
          fi

          if (( $(echo "$COVERAGE < 100.0" | bc -l) )); then
            echo "❌ Critical coverage < 100%"
            exit 1
          fi

          echo "✅ 80/20 validation passed"

      - name: Upload validation report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: 80-20-validation-report
          path: validation_output/validation_report.json
```

**What you gain**:
- ✅ **6x faster validation** (5s vs 30s)
- ✅ **Fast CI/CD gates** (no bottleneck)
- ✅ **Developer productivity** (instant feedback)
- ✅ **80% bug coverage** (critical paths validated)

**What you lose**:
- ⚠️ **20% of attributes** not validated (optional attributes)
- ⚠️ **20% of bugs** might slip through (non-critical paths)
- ⚠️ **Comprehensive coverage** (need strict mode for final release)

**When to use each mode**:
- **Minimal (60%)**: Local development, quick checks
- **80/20 (80%)**: ⭐ **CI/CD gates, PR validation** ⭐
- **Lenient (90%)**: QA environments, staging validation
- **Strict (100%)**: Final release validation, production certification

## 11. Architecture Decision Records

### ADR-001: Default to 80/20 Mode for CI/CD

**Status**: Proposed

**Context**: CI/CD pipelines are slow due to 30s+ validation. Developers wait >5 minutes for PR checks.

**Decision**: Make 80/20 mode the default for CI/CD gates. Use strict mode only for final releases.

**Rationale**:
- 80% bug coverage is sufficient for PR validation
- 6x faster validation improves developer productivity
- Critical attributes cannot be faked (no false positives)
- Final release still requires strict mode (100% coverage)

**Consequences**:
- **Positive**: Faster CI/CD, better developer experience
- **Negative**: 20% of bugs might slip through PR validation
- **Mitigation**: Require strict mode before release tag

### ADR-002: Critical Span Selection Criteria

**Status**: Proposed

**Context**: Need objective criteria for selecting "critical" spans.

**Decision**: A span is critical if it meets ANY of:
1. Cannot be faked (requires real infrastructure)
2. Proves core feature (primary framework capability)
3. High failure frequency (>10% of bugs)
4. User-facing (impacts end-user)
5. Resource lifecycle (tracks creation/cleanup)

**Rationale**: These criteria identify spans that provide maximum validation value.

**Consequences**: Clear, objective selection process for critical spans.

### ADR-003: Four Validation Levels

**Status**: Proposed

**Context**: One-size-fits-all validation doesn't work for all use cases.

**Decision**: Provide four validation levels:
1. **Minimal (60%)**: Local development
2. **80/20 (80%)**: CI/CD gates
3. **Lenient (90%)**: QA/staging
4. **Strict (100%)**: Final release

**Rationale**: Different use cases need different speed/coverage trade-offs.

**Consequences**: Flexibility for different validation scenarios.

```yaml
    validate_attributes: critical_and_required

  strict:

      - test.result
      - test.duration_ms
      - test.start_timestamp
      - test.end_timestamp
      - test.cleanup_performed

    risk_coverage: 30
    required_attributes:
      - container.id
      - container.created_at
      - container.destroyed_at
      - container.state
      - cleanup.success

  - id: span.clnrm.cli.health
    reason: "Validates system prerequisites"
    risk_coverage: 15
    required_attributes:
      - health.overall
      - docker.available
      - health.checks_total
      - operation.duration_ms

  - id: span.clnrm.plugin_lifecycle
    reason: "Core plugin system validation"

      - plugin.name
      - plugin.loaded
      - plugin.type
      - plugin.initialization_time_ms

  - id: span.clnrm.backend.operation
    reason: "Backend integration proof"

    required_attributes:
      - backend.type
      - backend.operation
      - operation.success

attribute_criticality:
```
