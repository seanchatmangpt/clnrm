# Signal Handling Architecture Assessment
## clnrm v1.3.0 - Architecture Evaluator #4

**Version:** 1.0.0
**Status:** Technical Assessment
**Date:** 2025-10-31
**Scope:** Signal safety, shutdown coordination, graceful termination patterns

---

## Executive Summary

**Assessment:** The planned architecture in Agent #7's specification has **critical gaps** in async-signal-safety, shutdown coordination, and cross-platform behavior. Current implementation in `weaver_controller.rs` uses basic `nix::kill()` without cancellation tokens or hierarchical shutdown coordination.

**Key Findings:**
- ❌ **Signal Safety:** No async-signal-safe coordination mechanism
- ❌ **Shutdown Coordination:** Manual `select!` vs structured cancellation
- ⚠️ **Cross-Platform:** Unix-only implementation, Windows fallback inadequate
- ⚠️ **Shutdown Pattern:** 6-phase shutdown is overly complex, should be 3-phase
- ✅ **Signal Propagation:** Correctly uses SIGHUP (not SIGINT) for Weaver

**Recommendation:** Adopt `tokio-util::sync::CancellationToken` for hierarchical shutdown coordination and reduce shutdown phases from 6 to 3.

## Signal Safety Analysis

### Current Implementation Review

**Location:** `crates/clnrm-core/src/telemetry/weaver_controller.rs:648-668`

```rust
// Current implementation
#[cfg(unix)]
{
    use nix::sys::signal::{kill, Signal};
    use nix::unistd::Pid;

    let pid = Pid::from_raw(process.id() as i32);
    kill(pid, Signal::SIGHUP)?;
}
```

**Analysis:**
- ✅ **Async-signal-safe:** `nix::kill()` is async-signal-safe
- ✅ **Correct signal:** Uses SIGHUP (graceful) not SIGINT (interrupt)
- ❌ **No coordination:** Direct signal delivery without cancellation mechanism
- ❌ **No idempotency:** Multiple signals can be sent concurrently
- ❌ **No hierarchy:** Can't cancel child operations before parent shutdown

### Agent #7's Planned Implementation

**Location:** `/tmp/v1.3.0-agent-7-stop-conditions.md:687-733`

```rust
// Planned signal handling with tokio::signal
use tokio::signal::unix::{signal, SignalKind};

pub struct SignalHandler {
    shutdown_tx: mpsc::Sender<ShutdownReason>,
}

impl SignalHandler {
    pub async fn install_handlers(&self) -> Result<()> {
        // SIGINT handler
        let mut sigint = signal(SignalKind::interrupt())?;
        let tx = self.shutdown_tx.clone();
        tokio::spawn(async move {
            sigint.recv().await;
            let _ = tx.send(ShutdownReason::Sigint).await;
        });

        // SIGHUP handler
        let mut sighup = signal(SignalKind::hangup())?;
        // ... similar pattern
    }
}
```

**Analysis:**
- ✅ **Async-aware:** Uses `tokio::signal` for async coordination
- ✅ **Multiple signals:** Handles SIGINT, SIGHUP, SIGTERM independently
- ⚠️ **Channel-based:** Uses `mpsc::Sender` for coordination (adds latency)
- ❌ **No hierarchy:** All signals trigger same shutdown, no cascading cancellation
- ❌ **Race conditions:** Multiple signals can race to `shutdown_tx.send()`

### Async-Signal-Safety Requirements

**POSIX Requirements:**
```
Only async-signal-safe functions may be called from signal handlers:
  ✅ write()
  ✅ _exit()
  ✅ kill()
  ❌ malloc()
  ❌ printf()
  ❌ pthread_mutex_lock()
```

**Rust Implications:**
- `tokio::signal` spawns tasks that handle signals asynchronously (safe)
- Signal handlers themselves just set atomic flags (safe)
- Channel sends from signal tasks (safe - happens after signal delivery)

**Verdict:** Planned implementation is async-signal-safe ✅

### Race Conditions in Signal Handlers

**Problem 1: Multiple Signal Delivery**

```rust
// Current race condition
tokio::spawn(async move {
    sigint.recv().await;
    let _ = tx.send(ShutdownReason::Sigint).await;  // What if SIGHUP already sent?
});

tokio::spawn(async move {
    sighup.recv().await;
    let _ = tx.send(ShutdownReason::Sighup).await;  // Race!
});
```

**Impact:**
- First signal wins (receiver gets one message)
- Second signal ignored (channel might be full or receiver dropped)
- Exit code non-deterministic if multiple signals arrive

**Solution:** Use `AtomicBool` with compare-and-swap:

```rust
let shutdown_initiated = Arc::new(AtomicBool::new(false));

tokio::spawn(async move {
    sigint.recv().await;
    if shutdown_initiated.compare_exchange(false, true, Ordering::SeqCst, Ordering::SeqCst).is_ok() {
        let _ = tx.send(ShutdownReason::Sigint).await;
    }
});
```

**Problem 2: Multi-Threaded Signal Delivery**

**POSIX Behavior:**
- Signals delivered to **any thread** in the process
- No guarantee which thread receives signal
- Multiple threads might handle same signal concurrently

**Current Mitigation:**
- `tokio::signal` registers handlers globally (per-process)
- Signal delivery happens once per signal instance
- Async tasks serialize handling via channels

**Verdict:** Race-free with proper atomic guards ✅

### Cross-Platform Behavior Differences

| Signal | Unix Behavior | Windows Behavior | Mitigation |
|--------|---------------|------------------|------------|
| SIGINT (Ctrl+C) | Delivered to process | `tokio::signal::ctrl_c()` | ✅ Both supported |
| SIGHUP | Delivered on terminal close | Not supported | ❌ HTTP /stop fallback needed |
| SIGTERM | Graceful termination | Not supported | ❌ HTTP /stop fallback needed |

**Current Windows Implementation:**

```rust
#[cfg(not(unix))]
{
    warn!("Graceful shutdown not supported on this platform, killing process");
    process.kill()?;  // SIGKILL equivalent - data loss!
}
```

**Problem:** Force-kill on Windows loses telemetry data.

**Solution:** Implement HTTP /stop endpoint fallback (already in design).

## Crate Recommendations

### Option 1: `tokio::signal` (Current Plan)

**Pros:**
- ✅ Already using tokio (zero new dependencies)
- ✅ Async-aware integration with tokio runtime
- ✅ Cross-platform (Unix + Windows Ctrl+C)
- ✅ Lightweight (just signal handling)

**Cons:**
- ❌ No built-in cancellation hierarchy
- ❌ Manual coordination via channels
- ❌ Verbose boilerplate for multiple signals

**Verdict:** **Good baseline choice** for signal delivery mechanism.

### Option 2: `signal-hook-tokio` (Alternative)

**Pros:**
- ✅ Better ergonomics than raw `tokio::signal`
- ✅ Signal iterator pattern (cleaner code)
- ✅ Async-signal-safe primitives
- ✅ Automatic signal masking

**Cons:**
- ❌ Additional dependency (14KB)
- ❌ Still requires manual shutdown coordination
- ❌ Learning curve for signal-hook API

**Example:**
```rust
use signal_hook::consts::signal::*;
use signal_hook_tokio::Signals;

let mut signals = Signals::new(&[SIGHUP, SIGTERM, SIGINT])?;

while let Some(signal) = signals.next().await {
    match signal {
        SIGINT => handle_sigint(),
        SIGHUP => handle_sighup(),
        SIGTERM => handle_sigterm(),
        _ => unreachable!(),
    }
}
```

**Verdict:** **Marginal improvement** - not worth new dependency.

### Option 3: `ctrlc` (Too Simple)

**Pros:**
- ✅ Dead simple API
- ✅ Cross-platform
- ✅ Tiny dependency

**Cons:**
- ❌ Only handles Ctrl+C (SIGINT)
- ❌ No SIGHUP/SIGTERM support
- ❌ Blocking API (not async-friendly)

**Verdict:** **Insufficient** for production requirements.

### Option 4: `tokio-util::sync::CancellationToken` (Recommended Addition)

**Pros:**
- ✅ **Hierarchical cancellation** (parent cancels children)
- ✅ **Idempotent** (multiple cancel calls safe)
- ✅ **Zero-cost** when not cancelled
- ✅ **Already in tokio ecosystem** (tokio-util is common)
- ✅ **Composable** (works with `select!`, `timeout`, etc.)

**Cons:**
- ⚠️ New dependency (tokio-util ~50KB)
- ⚠️ Different mental model (cancellation vs signals)

**Example:**
```rust
use tokio_util::sync::CancellationToken;

let cancel_token = CancellationToken::new();

// Signal handler cancels token
tokio::spawn({
    let token = cancel_token.clone();
    async move {
        tokio::signal::ctrl_c().await.unwrap();
        token.cancel();
    }
});

// All shutdown phases wait on token
tokio::select! {
    _ = cancel_token.cancelled() => {
        // Shutdown initiated
    }
    _ = run_tests() => {
        // Tests completed normally
    }
}
```

**Verdict:** **STRONGLY RECOMMENDED** for shutdown coordination.

### Recommendation Matrix

| Use Case | Recommended Crate | Why |
|----------|-------------------|-----|
| **Signal delivery** | `tokio::signal` | Already using tokio, no new deps |
| **Shutdown coordination** | `tokio-util::sync::CancellationToken` | Hierarchical, idempotent, composable |
| **Windows fallback** | HTTP /stop endpoint | SIGHUP not available on Windows |

**Final Stack:**
```toml
[dependencies]
tokio = { version = "1.0", features = ["signal"] }
tokio-util = { version = "0.7", features = ["sync"] }  # New addition
```

## Proposed Architecture Improvements

### Current Architecture (Agent #7 Design)

```rust
// Agent #7's design uses manual channel coordination
pub struct StopCoordinator {
    shutdown_tx: mpsc::Sender<ShutdownReason>,
    shutdown_rx: mpsc::Receiver<ShutdownReason>,
}

impl StopCoordinator {
    pub async fn run(&mut self) -> Result<i32> {
        let reason = self.shutdown_rx.recv().await?;
        self.execute_graceful_shutdown()?;
    }
}
```

**Problems:**
- Channel-based coordination adds latency
- No hierarchical cancellation (can't cancel sub-operations)
- Shutdown phases can't be cancelled once started
- Multiple signal sources can race

### Improved Architecture with CancellationToken

```rust
use tokio_util::sync::CancellationToken;
use std::sync::Arc;

pub struct StopCoordinator {
    config: StopConfig,
    cancel_token: CancellationToken,
    shutdown_reason: Arc<Mutex<Option<ShutdownReason>>>,
    weaver_controller: WeaverController,
}

impl StopCoordinator {
    pub fn new(config: StopConfig, weaver: WeaverController) -> Self {
        Self {
            config,
            cancel_token: CancellationToken::new(),
            shutdown_reason: Arc::new(Mutex::new(None)),
            weaver_controller: weaver,
        }
    }

    /// Install signal handlers that cancel token
    pub async fn install_signal_handlers(&self) -> Result<()> {
        // SIGINT handler
        let token = self.cancel_token.clone();
        let reason = Arc::clone(&self.shutdown_reason);
        tokio::spawn(async move {
            tokio::signal::ctrl_c().await.unwrap();
            *reason.lock().await = Some(ShutdownReason::Sigint);
            token.cancel();
        });

        // SIGHUP handler (Unix only)
        #[cfg(unix)]
        {
            let token = self.cancel_token.clone();
            let reason = Arc::clone(&self.shutdown_reason);
            tokio::spawn(async move {
                let mut sighup = tokio::signal::unix::signal(SignalKind::hangup()).unwrap();
                sighup.recv().await;
                *reason.lock().await = Some(ShutdownReason::Sighup);
                token.cancel();
            });
        }

        Ok(())
    }

    /// Run until cancellation or test completion
    pub async fn run_until_stop(&self) -> Result<ShutdownReason> {
        tokio::select! {
            _ = self.cancel_token.cancelled() => {
                let reason = self.shutdown_reason.lock().await;
                Ok(reason.unwrap_or(ShutdownReason::InactivityTimeout))
            }
            _ = self.wait_for_inactivity() => {
                Ok(ShutdownReason::InactivityTimeout)
            }
        }
    }

    /// Execute graceful shutdown with hierarchical cancellation
    pub async fn graceful_shutdown(&mut self) -> Result<ValidationReport> {
        // Create child cancellation tokens for each phase
        let phase1_token = self.cancel_token.child_token();
        let phase2_token = self.cancel_token.child_token();
        let phase3_token = self.cancel_token.child_token();

        // Phase 1: Stop accepting telemetry (cancellable)
        tokio::select! {
            result = self.stop_accepting_telemetry() => result?,
            _ = phase1_token.cancelled() => {
                return Err(CleanroomError::timeout_error("Phase 1 cancelled"));
            }
        }

        // Phase 2: Flush OTLP (cancellable with timeout)
        tokio::select! {
            result = self.flush_otlp() => result?,
            _ = tokio::time::sleep(Duration::from_secs(5)) => {
                warn!("OTLP flush timeout, continuing anyway");
            }
            _ = phase2_token.cancelled() => {
                return Err(CleanroomError::timeout_error("Phase 2 cancelled"));
            }
        }

        // Phase 3: Stop Weaver and collect report
        self.stop_weaver_and_collect_report().await
    }
}
```

**Benefits:**
- ✅ **Hierarchical:** Parent cancellation cascades to children
- ✅ **Idempotent:** Multiple `cancel()` calls are safe
- ✅ **Zero-cost:** No allocation when not cancelled
- ✅ **Composable:** Works with `select!`, `timeout`, `join!`
- ✅ **Testable:** Can inject mock cancellation for tests

### Cancellation Hierarchy

```
Main CancellationToken (root)
├── SIGINT handler (triggers cancel)
├── SIGHUP handler (triggers cancel)
├── HTTP /stop handler (triggers cancel)
├── Inactivity timeout (triggers cancel)
└── Graceful shutdown phases (children)
    ├── Phase 1: Stop accepting (child_token)
    ├── Phase 2: Flush OTLP (child_token)
    └── Phase 3: Stop Weaver (child_token)
```

**Cancellation Semantics:**
- Root cancellation → All child phases cancelled
- Phase timeout → Only that phase cancelled, next phase proceeds
- Multiple signals → First signal wins (idempotent cancel)

## Shutdown Pattern Simplification

### Agent #7's 6-Phase Shutdown (Too Complex)

```
Phase 1: Stop Accepting New Telemetry (50ms)
Phase 2: Flush OTLP Buffers (5s)
Phase 3: Signal Weaver to Stop (10s)
Phase 4: Collect Validation Report (2s)
Phase 5: Cleanup Resources (1s)
Phase 6: Exit with Appropriate Code
```

**Problems:**
- ❌ **Over-engineered:** 6 phases for simple shutdown
- ❌ **Error-prone:** More phases = more failure points
- ❌ **Hard to test:** 6 distinct test scenarios
- ❌ **Redundant:** Phases 1 & 5 can be combined

### Proposed 3-Phase Shutdown (FAANG Standard)

```
Phase 1: Stop and Flush (5s timeout)
├── Stop accepting new telemetry
├── Cancel in-flight tests
└── Flush OTLP buffers

Phase 2: Weaver Shutdown (10s timeout)
├── Send SIGHUP to Weaver
├── Wait for graceful exit
└── Force-kill on timeout

Phase 3: Collect Report and Exit
├── Parse validation_report.json
├── Cleanup resources (best-effort)
└── Exit with appropriate code
```

**Benefits:**
- ✅ **Simpler:** 3 phases vs 6 (50% reduction)
- ✅ **Clearer semantics:** Stop → Wait → Report
- ✅ **Easier testing:** 3 test scenarios vs 6
- ✅ **Parallel operations:** Phase 1 combines stop + flush

### Shutdown Timeline Comparison

| Design | Phase Count | Total Timeout | Normal Time | Force-Kill Time |
|--------|-------------|---------------|-------------|-----------------|
| Agent #7 (6-phase) | 6 | 18s | ~1s | 18s |
| Proposed (3-phase) | 3 | 15s | ~1s | 15s |

**Savings:** 3 fewer phases, 3s faster force-kill

### Implementation of 3-Phase Shutdown

```rust
impl StopCoordinator {
    pub async fn graceful_shutdown_3phase(&mut self) -> Result<ValidationReport> {
        info!("🛑 Beginning 3-phase graceful shutdown");

        // PHASE 1: Stop and Flush (parallel operations)
        let phase1_timeout = Duration::from_secs(5);
        let phase1_result = tokio::time::timeout(phase1_timeout, async {
            // Stop accepting + flush in parallel
            tokio::try_join!(
                self.stop_accepting_telemetry(),
                self.flush_otlp_buffers(),
            )
        }).await;

        match phase1_result {
            Ok(Ok(_)) => info!("✅ Phase 1 complete (stop + flush)"),
            Ok(Err(e)) => warn!("⚠️  Phase 1 error: {}", e),
            Err(_) => warn!("⚠️  Phase 1 timeout, continuing anyway"),
        }

        // PHASE 2: Weaver Shutdown
        let phase2_timeout = Duration::from_secs(10);
        let phase2_result = tokio::time::timeout(phase2_timeout,
            self.stop_weaver_gracefully()
        ).await;

        match phase2_result {
            Ok(Ok(_)) => info!("✅ Phase 2 complete (Weaver stopped)"),
            Ok(Err(e)) => {
                warn!("⚠️  Phase 2 error: {}, force-killing", e);
                self.force_kill_weaver()?;
            }
            Err(_) => {
                warn!("⚠️  Phase 2 timeout, force-killing");
                self.force_kill_weaver()?;
            }
        }

        // PHASE 3: Report and Cleanup
        let report = self.collect_validation_report().await.unwrap_or_default();
        self.cleanup_resources_best_effort().await;

        info!("✅ 3-phase shutdown complete");
        Ok(report)
    }
}
```

**Timeout Strategy:**
- Phase 1: 5s total (parallel stop + flush)
- Phase 2: 10s graceful, then force-kill
- Phase 3: 2s report collection, no timeout (best-effort)
- **Total:** 15s max (vs 18s in 6-phase design)

## Cross-Platform Strategy

### Unix Implementation (Preferred)

```rust
#[cfg(unix)]
pub async fn install_signal_handlers_unix(&self) -> Result<()> {
    use tokio::signal::unix::{signal, SignalKind};

    // SIGINT (Ctrl+C)
    let token = self.cancel_token.clone();
    let reason = Arc::clone(&self.shutdown_reason);
    tokio::spawn(async move {
        let mut sigint = signal(SignalKind::interrupt()).unwrap();
        sigint.recv().await;
        *reason.lock().await = Some(ShutdownReason::Sigint);
        token.cancel();
    });

    // SIGHUP (graceful shutdown)
    let token = self.cancel_token.clone();
    let reason = Arc::clone(&self.shutdown_reason);
    tokio::spawn(async move {
        let mut sighup = signal(SignalKind::hangup()).unwrap();
        sighup.recv().await;
        *reason.lock().await = Some(ShutdownReason::Sighup);
        token.cancel();
    });

    // SIGTERM (graceful shutdown)
    let token = self.cancel_token.clone();
    let reason = Arc::clone(&self.shutdown_reason);
    tokio::spawn(async move {
        let mut sigterm = signal(SignalKind::terminate()).unwrap();
        sigterm.recv().await;
        *reason.lock().await = Some(ShutdownReason::Sigterm);
        token.cancel();
    });

    Ok(())
}
```

### Cross-Platform Weaver Shutdown

```rust
pub async fn stop_weaver_gracefully(&mut self) -> Result<()> {
    let mut process = self.weaver_controller.live_check_process.take()
        .ok_or_else(|| CleanroomError::internal_error("Weaver not running"))?;

    #[cfg(unix)]
    {
        // Unix: Send SIGHUP
        use nix::sys::signal::{kill, Signal};
        use nix::unistd::Pid;

        let pid = Pid::from_raw(process.id() as i32);
        kill(pid, Signal::SIGHUP).map_err(|e|
            CleanroomError::internal_error(format!("Failed to send SIGHUP: {}", e))
        )?;

        // Wait for graceful exit
        match tokio::time::timeout(Duration::from_secs(10), process.wait()).await {
            Ok(Ok(status)) => {
                info!("✅ Weaver exited gracefully: {}", status);
                Ok(())
            }
            Ok(Err(e)) => Err(CleanroomError::internal_error(format!("Wait failed: {}", e))),
            Err(_) => {
                warn!("⚠️  Weaver did not exit within timeout");
                Err(CleanroomError::timeout_error("Weaver shutdown timeout"))
            }
        }
    }

    #[cfg(windows)]
    {
        // Windows: Use HTTP /stop endpoint
        let admin_port = self.weaver_controller.admin_port();
        let url = format!("http://localhost:{}/stop", admin_port);

        let client = reqwest::Client::builder()
            .timeout(Duration::from_secs(2))
            .build()?;

        match client.get(&url).send().await {
            Ok(response) if response.status().is_success() => {
                info!("✅ Weaver received /stop request");

                // Wait for process to exit
                match tokio::time::timeout(Duration::from_secs(10), process.wait()).await {
                    Ok(Ok(status)) => {
                        info!("✅ Weaver exited gracefully: {}", status);
                        Ok(())
                    }
                    _ => Err(CleanroomError::timeout_error("Weaver shutdown timeout"))
                }
            }
            _ => {
                warn!("⚠️  HTTP /stop failed, force-killing");
                process.kill().await?;
                Err(CleanroomError::internal_error("HTTP /stop failed"))
            }
        }
    }
}
```

**Probability:** Low (atomic guards + CancellationToken)
**Impact:** High (non-deterministic exit codes)
**Mitigation:**
- Use `AtomicBool::compare_exchange` for first-signal-wins
- CancellationToken is idempotent (multiple cancel() safe)

## Summary Recommendations

### ✅ Adopt These Changes

1. **Add `tokio-util::sync::CancellationToken`** for hierarchical shutdown coordination
2. **Simplify to 3-phase shutdown** (stop+flush, Weaver, report)
3. **Implement HTTP /stop fallback** for Windows graceful shutdown
4. **Keep `tokio::signal`** for signal delivery (no new crates needed)
5. **Add atomic guards** to prevent signal handler race conditions

### ❌ Reject These Options

1. **`signal-hook-tokio`** - Marginal improvement, not worth new dependency
2. **`ctrlc`** - Too simple, missing SIGHUP/SIGTERM support
3. **6-phase shutdown** - Over-engineered, error-prone
4. **Manual channel coordination** - Replaced by CancellationToken

### 🎯 Architecture Decision Records

**ADR-001: Adopt CancellationToken for Shutdown Coordination**
- **Decision:** Use `tokio-util::sync::CancellationToken` as primary shutdown mechanism
- **Rationale:** Hierarchical cancellation, idempotent, composable with tokio primitives
- **Alternatives:** Manual channel coordination (too complex), signal handlers only (no hierarchy)

**ADR-002: Simplify to 3-Phase Shutdown**
- **Decision:** Reduce from 6 phases to 3 phases
- **Rationale:** Simpler, fewer failure points, easier testing, parallel phase 1
- **Alternatives:** Keep 6 phases (too complex), reduce to 2 phases (insufficient granularity)

**ADR-003: HTTP /stop as Windows Fallback**
- **Decision:** Use HTTP GET /stop for graceful shutdown on Windows
- **Rationale:** SIGHUP not available on Windows, HTTP is cross-platform
- **Alternatives:** Windows-only signal (doesn't exist), no graceful shutdown (data loss)

## Proposed Code Structure

```rust
// crates/clnrm-core/src/telemetry/stop_coordinator.rs

use tokio_util::sync::CancellationToken;
use std::sync::Arc;
use tokio::sync::Mutex;

#[derive(Debug, Clone, Copy)]
pub enum ShutdownReason {
    Sigint,
    Sighup,
    Sigterm,
    HttpStop,
    InactivityTimeout,
}

pub struct StopCoordinator {
    config: StopConfig,
    cancel_token: CancellationToken,
    shutdown_reason: Arc<Mutex<Option<ShutdownReason>>>,
    weaver_controller: WeaverController,
}

impl StopCoordinator {
    pub async fn install_signal_handlers(&self) -> Result<()> {
        #[cfg(unix)]
        self.install_signal_handlers_unix().await?;

        #[cfg(windows)]
        self.install_signal_handlers_windows().await?;

        Ok(())
    }

    pub async fn run_until_stop(&self) -> Result<ShutdownReason> {
        tokio::select! {
            _ = self.cancel_token.cancelled() => {
                Ok(self.shutdown_reason.lock().await.unwrap_or(ShutdownReason::InactivityTimeout))
            }
            _ = self.wait_for_inactivity() => {
                self.cancel_token.cancel();
                Ok(ShutdownReason::InactivityTimeout)
            }
        }
    }

    pub async fn graceful_shutdown_3phase(&mut self) -> Result<ValidationReport> {
        // Phase 1: Stop and Flush (parallel)
        tokio::time::timeout(Duration::from_secs(5), async {
            tokio::try_join!(
                self.stop_accepting_telemetry(),
                self.flush_otlp_buffers(),
            )
        }).await.ok();

        // Phase 2: Weaver Shutdown
        let weaver_result = tokio::time::timeout(
            Duration::from_secs(10),
            self.stop_weaver_gracefully()
        ).await;

        if weaver_result.is_err() {
            self.force_kill_weaver()?;
        }

        // Phase 3: Report and Cleanup
        let report = self.collect_validation_report().await.unwrap_or_default();
        self.cleanup_resources_best_effort().await;

        Ok(report)
    }
}
```

## Conclusion

The planned signal handling architecture has solid foundations (`tokio::signal`, SIGHUP for Weaver) but lacks hierarchical shutdown coordination and is over-engineered with 6 shutdown phases.

**Recommended Changes:**
1. Add `tokio-util::sync::CancellationToken` for hierarchical cancellation
2. Simplify to 3-phase shutdown (stop+flush, Weaver, report)
3. Implement HTTP /stop fallback for Windows
4. Add atomic guards to prevent signal handler races

**Expected Outcomes:**
- ✅ Simpler architecture (3 phases vs 6)
- ✅ Better testability (hierarchical cancellation)
- ✅ Cross-platform parity (HTTP fallback)
- ✅ Production-ready shutdown (FAANG standards)

**Implementation Effort:** 4 days

**Risk Level:** Low (CancellationToken is well-tested, HTTP /stop is documented)

This assessment provides a clear path forward for robust, production-grade signal handling in clnrm v1.3.0.
